# Много городов и стран: как это устроено

**Смотреть сюда перед тем, как добавлять город, страну или язык.** Здесь
описано, что делает сайт сам, что нужно положить в данные и где
пределы бесплатной инфраструктуры. Решение владельца (2026-09-25):
заложить масштабирование сразу, до того как городов станет много.

Связанные документы:
- `docs/playbooks/add-city.md` — как собрать данные города;
- `docs/card-spec.md` — что в карточке заведения;
- `docs/database.md` — база, миграции, seed, вместимость;
- `docs/seo/README.md` — адреса, языки, индексация.

## 1. Главный принцип: город — это только данные

Новый город появляется на сайте без правок кода. Нужна папка
`data/cities/<slug>/` и мердж PR в `main`. Дальше production-сборка
запускает seed, город попадает в базу, и сразу работают:

| Что | Адрес (EN / местный язык) |
|---|---|
| Страница города (хаб) | `/city/<город>/`, `/sk/mesto/<город>/` |
| Список категории | `/grooming/<город>/`, `/sk/psi-salon/<город>/` |
| Район | `/grooming/<город>/<район>/` |
| Круглосуточные ветклиники | `/vet-clinics/<город>/nonstop/` |
| Карточка заведения | `/business/<slug>/`, `/sk/podnik/<slug>/` |
| Sitemap, `llms.txt`, колонка «Города» в футере | автоматически |

Страница категории, района или города индексируется, только если на
ней не меньше 3 заведений (`docs/seo/README.md` §2.3).

## 2. Что город задаёт в `city.json`

Все настройки, которые отличают один город от другого, лежат в данных,
а не в коде:

| Поле | Зачем | Пример |
|---|---|---|
| `name`, `slug` | название и адрес | `"Wien"`, `"vienna"` |
| `country` | код страны ISO | `"AT"` |
| `locales` | языки страниц кроме английского, главный первым. Английский сайт добавляет всегда. Пустой список `[]` — город только на английском (США, Великобритания) | `["de"]` |
| `locale` | старое поле, главный язык. Используется, если нет `locales` | `"de"` |
| `timezone` | для «Открыто сейчас» и часов работы. **Обязательно**, имя из базы IANA | `"Europe/Vienna"` |
| `currency` | валюта цен в `prices.csv`. **Обязательно** | `"EUR"`, `"USD"`, `"CZK"` |
| `in_city` | «в городе» на каждом языке, с правильным падежом. Без него: `in <name>` на английском и `– <name>` на других языках | `{"en": "in Vienna", "de": "in Wien"}` |
| `lat`, `lng` | центр города для «Рядом со мной» и выбора города | `48.2082`, `16.3738` |

Без `timezone` или `currency` seed останавливается с понятной ошибкой:
город с неверным временем «Открыто сейчас» хуже, чем город, который
не загрузился.

## 3. Страны и языки

- **Язык страницы доступен, только если он есть у города.** Например,
  `/sk/psi-salon/new-york/` отдаёт 404, потому что у Нью-Йорка нет
  словацкого. Hreflang и sitemap строятся по `locales` каждого города.
- **Новая страна на уже поддерживаемом языке** (например, английский
  для США) — только данные.
- **Новая страна на новом языке** (немецкий, чешский …) требует разовой
  работы с кодом на каждый язык: перевод интерфейса, слаги категорий на
  этом языке и префикс `/de/`. Пока это делает «правая рука» или CLI.
  После этого все города на этом языке — снова только данные.
  Отдельная инструкция `docs/playbooks/add-language.md` будет, когда
  переводы вынесем в отдельные файлы по языкам.
- **Районы.** Определяются по координатам из границ OpenStreetMap
  (`website/scripts/fetch-districts.ts`), уровень административного
  деления для каждой страны свой, передаётся аргументом `admin_level`.
  Одинаковые названия районов в разных городах не мешают друг другу:
  адрес района всегда содержит город.
- **Slug заведения уникален на весь сайт** (`/business/<slug>/`). Если
  совпадёт с заведением другого города, seed остановится с ошибкой, и
  в конец slug нужно дописать город.

## 4. Почему сборка не растёт с городами

- Страницы городов, категорий и районов **не собираются заранее**, а
  рендерятся при первом запросе. Данные из базы кэшируются на сутки в
  кэше конкретного деплоя (`lib/data.ts`). Поэтому время сборки не
  зависит от числа городов: при сборке заранее готовятся около 15
  статических страниц.
- **Все запросы к базе ограничены городом.** Счётчики, фильтры, цены,
  районы и сводки считаются по одному городу, поэтому данные разных
  городов не смешиваются.
- **Карточка заведения** тоже рендерится по запросу.

## 5. Рейтинг Google: собираем вручную (решение владельца)

**Решение (2026-09-25):** рейтинг и число оценок Google собираем
**вручную** в ходе сбора данных по городу (`docs/card-spec.md`,
поля `google_rating`, `google_rating_count`, `rating_observed_at`).
Платный Google Places API не подключаем, **пока покрытие не дойдёт
примерно до 10 крупнейших городов США и столиц Европы**.

Почему:
- Это около 55 городов × ~100 заведений ≈ 5 500 карточек. Их можно
  собрать параллельно силами Antigravity, не тратя денег.
- При API каждое обновление всех рейтингов — это платные запросы (после
  бесплатной квоты — порядка $20 за 1 000). Проверять актуальные цены
  Google перед решением.
- Рейтинг меняется медленно. Для каталога достаточно обновлять его
  раз в несколько месяцев, при повторном проходе по городу.

Как держать рейтинги актуальными до перехода на API:
- у каждого рейтинга есть `rating_observed_at`;
- рейтинги старше ~6 месяцев обновляются задачей на тот же город по
  `docs/playbooks/add-city.md` (обновить только три поля рейтинга);
- рейтинг, у которого меньше 5 оценок, не показываем (правило из
  `card-spec.md`).

Когда пересмотреть: после ~55 городов или раньше, если ручное
обновление станет узким местом. Тогда нужно решить: API с платой за
обновление или ручной сбор дальше. Перед переходом на API прочитать
условия Google: сколько времени можно хранить данные Places.

## 6. Пределы бесплатной инфраструктуры

| Ресурс | Предел | Когда упрёмся |
|---|---|---|
| Место в Neon Free (0,5 ГБ) | ~1 300 городов по 100 заведений | Не скоро (`docs/database.md`) |
| Время работы Neon (100 CU-часов в месяц) | Суточный кэш снимает почти всю нагрузку | При большом трафике |
| Сборка Vercel (45 минут) | Страницы не собираются заранее; seed загружает только изменившиеся города, пачками (`docs/database.md`) | Не упираемся: сборка почти не зависит от числа городов |
| Vercel Hobby (функции, трафик) | Рендер по запросу с кэшем | При большом трафике — тариф Pro |

## 7. Проверка на тестовых городах

`website/prisma/fixtures/cities/` — два выдуманных города:
- `testville` (SK, словацкий);
- `testburg` (US, только английский, у районов те же slug, что у
  testville).

Их загружают в отдельную локальную базу (`website/prisma/fixtures/README.md`)
и проверяют:
- у testburg нет словацких страниц;
- районы с одинаковым slug показывают только заведения своего города;
- хабы, sitemap и nonstop-страница работают для обоих городов.

# SEO и LLM: решения, их причины и история

**Смотреть сюда в первую очередь.** Здесь собраны все принятые решения
про SEO и LLM и то, на чём каждое из них основано. Подробности — в
файлах по ссылкам. Новое решение по SEO записывается сюда (раздел 2 и
журнал в разделе 5), а не только в PR или задачу.

Источники, на которые ссылается этот файл:
- `PRODUCT.md` — концепция владельца: трафик из SEO и LLM, mobile
  first, работа по всему миру;
- `docs/design-plan.md` §2.2 (языки), §3 (URL), раздел про LLM;
- `docs/seo/english-keywords.md` — исследование английских запросов
  (Antigravity);
- `docs/database.md` — база и кэш (связь с доступностью сайта).

---

## 1. Цель и рамка ожиданий

- **Трафик — из поиска (Google, Bing) и из ответов ИИ-ассистентов**
  (ChatGPT, Claude, Gemini, Perplexity). Источник: `PRODUCT.md`.
- **ИИ-ассистенты почти всегда берут ответы из тех же поисковых
  индексов** (Bing, частично Google). Поэтому «SEO для LLM» — это в
  основном обычное SEO плюс несколько дешёвых дополнений (раздел 2.6).
  Источник: `docs/design-plan.md`, раздел про LLM.
- **Основной спрос — на местном языке.** Английских запросов по
  Братиславе примерно 100–400 в месяц на все 6 категорий, словацких —
  в 10–15 раз больше. Зато у английских почти нет конкурентов, и за
  ними стоят люди, готовые платить. Источник:
  `docs/seo/english-keywords.md` §1.

### 2.2 Языки (hreflang)
- **Языковая модель v2 — сделано 2026-09-25** (владелец, решение от
  2026-09-23 подтверждено 2026-09-25; `design-plan.md` §2.2):
  - префикс у каждого языка, английского тоже: `/en/vet-clinics/…`,
    `/sk/veterinar/…`;
  - старые английские адреса без префикса — **301** на `/en/…` с теми
    же параметрами (список первых сегментов — `LEGACY_EN_SEGMENTS` в
    `lib/locales.ts`); остальные адреса без префикса — 404;
  - **только корень `/`** выбирает язык и отдаёт **307**: cookie
    `pawenn_lang` (ставит переключатель языка) → `Accept-Language` →
    страна (`CF-IPCountry` от Cloudflare, иначе `x-vercel-ip-country`)
    через `COUNTRY_LANGUAGE` → английский. `Vary: Cookie,
    Accept-Language, CF-IPCountry`, `Cache-Control: private, no-store`.
    Никакой другой адрес не смотрит на cookie/браузер/страну — иначе
    ломается индексация.
- **canonical и hreflang:** каждая страница — сама себе canonical, все
  её языковые версии в hreflang. `x-default`: у главной — корень `/`,
  у остальных — английская версия (у внутренних страниц нет
  «страницы выбора языка»). В sitemap — то же через `xhtml:link`; в
  sitemap только адреса с префиксом.
- **Переключатель языка** ведёт на ту же страницу на другом языке
  (категории, карточки, хаб города, страницы цен со слагами услуг) и
  пишет cookie `pawenn_lang` на год. Упомянуть её в политике
  конфиденциальности — за владельцем.
- **Справка и юридические страницы** пока только на английском
  (`/en/how-it-works/` и т.д.); с других языков — ссылка с пометкой
  «(EN)». Переводятся на язык города по мере надобности.
- Код: `lib/locales.ts` (`localePath`, `pickLocale`,
  `COUNTRY_LANGUAGE`), `proxy.ts`, `lib/localeSwitch.ts`, `lib/seo.ts`
  (`localeAlternates`), `app/sitemap.ts`.
- **Что проверить после выкладки:** в Search Console отправить
  `sitemap.xml` заново; «Проверка URL» для `/en/` и `/sk/`. Старые
  адреса выпадут из индекса и заменятся новыми за 1–3 недели.

### 2.3 Что индексируется
- **Страница категории или района индексируется, если на ней не меньше
  3 заведений.** Меньше — `noindex, follow`, и в sitemap её нет.
  Причина: пустые страницы Google считает мусором, и это тянет вниз
  весь сайт. Источник: `docs/concept.md`, `design-plan.md` §3. Код:
  `robots` в `generateMetadata` страниц категории и района.
- **Варианты страницы с фильтрами** (`?animal=`, `?near=`) не
  индексируются отдельно: их canonical указывает на страницу без
  фильтров.
- **Не индексируются:** политика конфиденциальности, условия
  использования, страница 404.
- **`robots.txt` разрешает всё, включая ИИ-краулеров** (GPTBot,
  ClaudeBot, anthropic-ai, Google-Extended, PerplexityBot, CCBot).
  Причина: нам нужно, чтобы ИИ нас цитировали; `design-plan.md`,
  раздел про LLM.

- **Районы — только для SEO, выбора района в интерфейсе нет** (решение
  владельца, 2026-09-25):
  - в поиске поле «Where» — это город, человек его вписывает, есть
    подсказки и кнопка «Рядом со мной»;
  - в списках — «Рядом со мной» (сортировка по расстоянию);
  - выпадающий список районов, боковой список «По районам» и блок
    районов на главной убраны.
- **Страницы районов остаются** с теми же адресами, в sitemap, если там
  ≥ 3 заведений. Внутренние ссылки на них идут из текста: на странице
  заведения строка «Psí salón v mestskej časti Ružinov, Bratislava» /
  «Grooming salon in Ružinov, Bratislava» (район — ссылка), плюс хлебные
  крошки. Ссылка ставится, только если в районе ≥ 3 заведений этой
  категории. Код: `lib/districts.ts`.
- **Если в Search Console просядут районные запросы** — добавить внизу
  страницы города строку текстовых ссылок на районы (не элемент выбора).
- **Страницы по признакам** (владелец, 2026-09-25; `lib/attributePages.ts`) —
  список одной категории города, суженный до признака, который люди ищут.
  Свой адрес, заголовок и ответ одной фразой («V nedeľu má otvorené 9 z 34
  veterinárnych ambulancií»). Для ветклиник:

  | Признак | SK | EN | Условие | В индексе от |
  |---|---|---|---|---|
  | Nonstop | `/sk/veterinar/<город>/nonstop/` | `/en/vet-clinics/<город>/nonstop/` | `emergency_24_7` | 1 места |
  | Суббота | `…/sobota/` | `…/open-saturday/` | часы в субботу или nonstop | 3 мест |
  | Воскресенье | `…/nedela/` | `…/open-sunday/` | часы в воскресенье или nonstop («только по записи» — нет) | 3 мест |
  | Экзоты | `…/exoticke-zvierata/` | `…/exotic-animals/` | `specialties` содержит `exotics` | 3 мест |
  | Выезд на дом | `…/vyjazd-domov/` | `…/home-visits/` | `home_visits=yes` | 3 мест |

  - Страница существует, пока в городе есть хотя бы одно такое место; ниже
    порога — `noindex, follow` и не в sitemap. Новые города получают их сами.
  - **Только признаки с реальным спросом.** Не делать страницу на каждую
    специализацию (кардиология, офтальмология…): это тонкий однотипный
    контент.
  - **Кнопки в списке — как остальные фильтры** (владелец: без лишних
    цветов): нейтральные, выбранная залита тёмным и ведёт обратно ко всему
    списку. На странице города — только «Nonstop 24/7».
  - **Nonstop — только реально круглосуточные** (правило владельца
    2026-09-25, `docs/card-spec.md` раздел 8, проверка в `check-city`).
    Дежурный телефон или ночная неотложка при обычных часах — не nonstop.
  - Общий FAQ категории на этих страницах не показывается (он про всех и
    повторяет страницу категории).
- **Фильтры** «Открыто сейчас» (`?open=1`), рейтинг и сортировка — это
  варианты страницы. Их canonical указывает на страницу без фильтров.

### 2.3.1 Страницы цен (владелец, 2026-09-25)
- **Обзор цен категории:** `/<категория>/<город>/prices/`, SK
  `/sk/<категория>/<город>/ceny/` — медиана, разброс и число заведений
  по каждой услуге. Существует, пока хотя бы у одной услуги есть
  рыночная цена.
- **Страница услуги:** `/…/prices/<услуга>/`, SK `/…/ceny/<услуга>/`
  (`/sk/veterinar/bratislava/ceny/kastracia-kocura/`). Слаги услуг — руками
  в `lib/pricePages.ts`, так, как люди ищут. Сверху — ответ одной фразой
  (от–до, медиана, сколько мест, дата проверки), это же — `FAQPage`
  JSON-LD для ИИ; дальше таблица мест по цене с «выше/ниже рынка» и
  кнопкой «Позвонить»; отдельно — цены, которые не сравниваем.
- **Индексация:** `index` и sitemap, только если сравнимых цен ≥ 3
  (`MIN_PLACES` в `lib/priceMarket.ts`, то же правило, что у районов). Меньше —
  страница открывается, но `noindex, follow`. Нет ни одной цены — 404.
  `lastmod` — дата самой свежей проверки цен.
- **Ссылки на них:** из таблицы цен на карточке заведения (название
  услуги), кнопка «Ceny v Bratislave» на странице категории, `llms.txt`.
- Логика расчёта — `docs/card-spec.md`, «Сравнение с рынком города».
  Новый город получает страницы сам, когда в нём наберутся цены.

### 2.4 Заголовки и описания (title / meta description)
- **Английский title страницы категории** отвечает на то, как ищут
  люди, а не повторяет название раздела (решение от 2026-09-24):

  | Категория | Title |
  |---|---|
  | Груминг | Dog & Cat Grooming in {город} \| Pawenn |
  | Ветеринары | Vets & Veterinary Clinics in {город} \| Pawenn |
  | Отели | Pet Hotels & Dog Boarding in {город} \| Pawenn |
  | Дрессировка | Dog Training & Puppy Classes in {город} \| Pawenn |
  | Зоомагазины | Pet Shops in {город} \| Pawenn |
  | Ситтинг | Pet Sitters & Dog Walkers in {город} \| Pawenn |

  Причины:
  - Раньше title был «Grooming in Bratislava», а такой запрос Google
    понимает и как барбершопы: в выдаче по нему соседствуют
    Shelbyland, Gentleman's World и Štýl.
  - Формулировки взяты из `english-keywords.md` §2 (колонка
    «Candidate H1 & Page Title»).
  - Бренд в конце title нужен, чтобы в выдаче было видно, чей это сайт.

  Код: `SEO_TITLE` в `lib/categories.ts`.
- **Meta description и текст на странице** используют существительное во
  множественном числе («Compare 10 grooming salons in Bratislava…»), а
  не название раздела («Browse 10 grooming» — было грамматически
  неверно). Код: `PLURAL` в `lib/categories.ts`.
- **Словацкие title** пока совпадают с названиями разделов (плюс
  `| Pawenn`). Формулировку поменяем после
  `tasks/antigravity-slovak-keyword-research.md`.
- **H1 пока не меняли:** он остаётся коротким («Grooming in
  Bratislava»), потому что это элемент дизайна. Можно вернуться к нему,
  если позиции не вырастут.

### 2.5 Структурированные данные (JSON-LD)
- **Главная:** `Organization` (имя, логотип `/brand/logo.png`) и
  `WebSite` — одна сущность бренда для поиска и ИИ (2026-09-25).
- **Карточка заведения:** самый точный тип — `VeterinaryCare` для
  ветклиник, `PetStore` для зоомагазинов, остальные `LocalBusiness`;
  адрес, координаты, телефон, `sameAs` (сайт и Google Maps), логотип,
  `openingHoursSpecification` из часов работы, `priceRange` (€–€€€€€ из
  сравнения с рынком города). `AggregateRating` — **только по нашим
  собственным отзывам**; рейтинг Google в разметку не ставится никогда.
- **Списки (город, категория, район):** `ItemList` с карточками в
  порядке показа.
- **Хлебные крошки:** `BreadcrumbList` на каждой странице с крошками
  (компонент `Breadcrumbs`). Порядок: Главная › Город › Категория ›
  Район › Заведение; город ведёт на хаб города.
- **Страница категории:** `FAQPage`. Вопросы и ответы генерируются из
  данных: сколько заведений, диапазон цен, сколько проверено. Их не
  нужно писать руками под каждый город. Источник: `design-plan.md`,
  раздел про LLM, пп. 2–3. Rich-сниппеты FAQ Google с 2023 года
  показывает почти только гос- и медсайтам, ценность — в тексте.

### 2.5.1 Превью ссылок (Open Graph, Twitter)
- На всех страницах: `og:title`, `og:description`, `og:url`,
  `og:locale` (`sk_SK` / `en_US`) + `og:locale:alternate`, картинка
  1200×630, `twitter:card=summary_large_image` (`lib/seo.ts`,
  `socialMeta`).
- Картинка рисуется сама для каждой страницы: логотип, название,
  подзаголовок, цвет категории (`app/api/og/route.tsx`). Своих фото
  заведений не используем (см. `docs/card-spec.md`, `photo_urls`).

### 2.5.2 Title и description карточки заведения
- Title: `{Название} – {Район}, {Город} | Pawenn`, укорачивается до ~60
  символов (сначала бренд, потом город).
- Description: название, адрес, короткое описание заведения и хвост
  «часы, цены, звонок…»; слово «ceny/prices» — только если у места есть
  цены.

### 2.6 Отдельно для LLM
- **`/llms.txt`** — короткое описание сайта и ссылки на главные
  страницы. Код: `app/llms.txt/route.ts`.
- **Bing Webmaster Tools** — ручной шаг владельца: индекс Bing питает
  Copilot и часть поиска ChatGPT.

### 2.7 Аналитика
- **Vercel Web Analytics** (`<Analytics />` в `app/[lang]/layout.tsx`,
  пакет `@vercel/analytics`): посещения, страницы, источники трафика,
  страны. Работает без cookie, поэтому баннер согласия не нужен.
  Бесплатный тариф Hobby — до 50 000 событий в месяц. Включается один
  раз владельцем: Vercel → проект → Analytics → Enable.
- **Google Search Console** — запросы, позиции и клики из поиска
  (раздел 3).

### 2.8 Скорость и доступность
- **Чтения из базы кэшируются на сутки** (`lib/data.ts`). Страница
  отдаётся быстро и не падает, если база временно недоступна
  до истечения кэша. Причина: инцидент 2026-09-24 (раздел 4).
- **`lastmod` в sitemap** у карточек — самая свежая дата проверки чего-либо
  на странице (часы, рейтинг, цены, ручная проверка), не «сегодня».
- **Mobile first** — основной посетитель с телефона. Источник:
  `PRODUCT.md`.

### 2.9 Только HTTPS
- **Любой `http://` запрос получает 301 на `https://`.** Делает это
  Cloudflare: SSL/TLS → Edge Certificates → **Always Use HTTPS** (включено
  владельцем 2026-09-25, проверено в инкогнито). Vercel сам этого не
  сделает: Cloudflare ходит к нему по https, даже когда посетитель пришёл
  по http, поэтому без этой настройки сайт отвечал 200 и по http.
- **Шифрование Cloudflare → Vercel:** Full (Strict) — у Vercel настоящий
  сертификат. Flexible нельзя: с Vercel даёт бесконечный редирект.
- **Код:** адрес сайта — только `SITE_URL` (`lib/site.ts`, по умолчанию
  `https://pawenn.com`); canonical, sitemap, robots, JSON-LD и
  `llms.txt` берут его оттуда. Если на Vercel задана
  `NEXT_PUBLIC_SITE_URL`, она обязана начинаться с `https://`.

## 4. Инциденты, которые повлияли на SEO

- **2026-09-24: страницы с данными из базы отдавали 500 примерно
  полдня.** Закончился бесплатный лимит Prisma Postgres, 100 тыс.
  операций. Роботы, заходившие в это время, видели ошибку.
  Исправление: переезд на Neon и кэш на сутки
  (PR #52, `docs/database.md`). Что проверить: отчёт «Страницы» в
  Search Console, ошибки 5xx → «Проверить исправление».

- **До 2026-09-25: сайт отвечал и по `http://` без редиректа.** Google
  проиндексировал часть адресов с `http://`. Исправление: Always Use HTTPS
  в Cloudflare (раздел 2.9). Canonical везде был на `https`, поэтому
  Google сам склеит версии. Что проверить: Search Console, лучше
  «Доменный ресурс» `pawenn.com` — через 1–3 недели `http://` адреса
  должны уйти из «Проиндексировано».

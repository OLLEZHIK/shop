# Ключевые слова по языкам

Решение владельца (2026-09-26): **каждая страница называется так, как
люди чаще всего ищут её на своём языке.** Исследование идёт отдельно по
каждому языку сайта. Результат — заголовки, H1, описания и (редко)
адреса страниц по реальным запросам, а не по нашим догадкам.

| Язык | Файл | Статус |
|---|---|---|
| Словацкий (`sk`) | `sk.md` | Карта запросов готова, цифры собирает Antigravity: `tasks/antigravity-keywords-sk.md` |
| Английский (`en`) | `en.md` | Качественное исследование категорий — `../english-keywords.md` (без цифр). Цифры для новых типов страниц — `tasks/antigravity-keywords-en.md` |
| Новый язык | `<locale>.md` | Шаг в `docs/playbooks/add-language.md`: сначала запросы, потом слаги |

## 1. Как собирать цифры

Облачный Claude Code данные Google не видит (сеть закрыта), поэтому
цифры собирает агент на компьютере владельца (Antigravity) или сам
владелец. Источники по убыванию надёжности:

1. **Google Ads Keyword Planner** (бесплатно с аккаунтом Google Ads,
   кампанию запускать не нужно): «Узнать число запросов и прогнозы» →
   вставить все варианты из карты → Местоположение: страна (для `sk` —
   Slovakia; если даёт — отдельно Bratislava), Язык: язык страницы.
   Берём «Среднее число запросов в месяц». Без активной кампании
   Planner даёт диапазоны (10–100, 100–1K) — пишем диапазон как есть.
2. **Google Trends** (`trends.google.com`), страна, 12 месяцев:
   сравнить до 5 вариантов одного смысла. Нужен, когда Planner даёт
   одинаковый диапазон: Trends показывает, какой вариант больше.
3. **Подсказки Google** (`google.<tld>` в режиме инкогнито, язык
   страны): ввести основу («veterin», «strihanie ps») и записать
   подсказки. Так находятся варианты, которых нет в карте.
4. **«Похожие запросы» и «Люди также спрашивают»** внизу выдачи —
   идеи для FAQ и текстов.
5. **Google Search Console** сайта — после того как страницы
   поживут в индексе 2–3 месяца: реальные запросы, по которым нас
   показывают. Тогда карту пересматриваем по ним.

Каждая цифра — с источником и датой. Нет данных — пустая клетка, а
не оценка.

## 2. Формат таблицы в `<locale>.md`

Одна таблица на тип страницы. Варианты одного смысла — рядом:

| Смысл | Вариант запроса | Planner, мес. | Trends (0–100) | Подсказка | Решение |
|---|---|---|---|---|---|
| ветеринар в городе | veterinár bratislava | 1K–10K | 100 | да | **главный** |
| ветеринар в городе | veterina bratislava | 100–1K | 45 | да | второй: в описание |

`Решение`:
- **главный** — самый частый вариант смысла; идёт в `<title>` и H1;
- **второй** — заметный вариант: в meta description, подзаголовок,
  текст, FAQ (Google понимает синонимы, но совпадение слов помогает);
- **нет** — почти нет спроса, не используем.

## 3. Правила применения

- **Title и H1** — по главному варианту. Меняем свободно: это не
  ломает ссылки.
- **Адрес (слаг)** — живой и в индексе, поэтому меняем, только если
  главный вариант **явно** сильнее текущего (минимум на ступень
  Planner — например 1K–10K против 100–1K — или вдвое по Trends) и
  речь о странице с заметным спросом. Смена = 301 со старого адреса.
  Для нового языка слаги выбираем по исследованию **до** запуска.
- **Формы слов** — в словацком запросы бывают в разных падежах и
  числах («veterinár» / «veterinári»). Google их склеивает; выбираем
  форму, которая естественно читается в заголовке.
- **Диакритика** — люди часто пишут без неё («psi salon»). Для Google
  это один запрос; в текстах пишем правильно, в адресах — без неё.
- **Город и район** в запросе — отдельные строки карты нужны, только
  если у района своя страница (≥ 3 места). Смотрим, ищут ли «veterinár
  petržalka» — это решает, какие районы подсвечивать в ссылках.

## 4. Где это на сайте

| Что | Где в коде |
|---|---|
| Название категории, title, описание | `website/lib/categories.ts`: `LABELS`, `SEO_TITLE`, `BLURBS`, `SLUGS` |
| Страницы признаков (nonstop, sobota…) | `website/lib/attributePages.ts` (слаги), словарь `attributes` в `lib/dictionaries/<locale>.ts` |
| Страницы цен | `website/lib/priceSlugs.ts` (слаги услуг), `lib/services.ts` (названия), словарь `prices` |
| Главная, FAQ | словари `lib/dictionaries/<locale>.ts` |

Применяет результат исполнитель сайта (CLI, «правая» или «левая рука»)
отдельным PR, после мерджа файла `<locale>.md` с цифрами.

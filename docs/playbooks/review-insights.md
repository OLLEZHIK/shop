# Инструкция: «Что говорят клиенты» — сводка отзывов и FAQ

**Для кого:** исполнитель (Antigravity), любой город. Делается вторым
проходом после `businesses.csv` города (`docs/playbooks/add-city.md`).
Перед работой — `docs/playbooks/quality.md`.

## Зачем

Решение владельца (2026-09-24): на странице места показать, что клиенты
думают о нём за последние полгода — отношение, результат, цены, запись
и ожидание — и ответы на частые вопросы. Это **уникальный текст на
местном языке**, которого нет больше нигде: для SEO и для ответов
ИИ-ассистентов.

**Главное правило: это не отзывы, а наша сводка отзывов.** Не от лица
клиента, без авторов и своих звёзд. Текст, выданный за отзывы клиентов,
— фейковые отзывы: их запрещает закон ЕС о защите потребителей
(директива Omnibus), и Google наказывает за них весь сайт. Честная
сводка «многие пишут, что…» законна и для SEO ценнее.

## Для каких мест

- Места города с **≥ 20 оценками** Google (`google_rating_count`) и
  **≥ 5 отзывами с текстом за последние 6 месяцев**. Остальным файл не
  создавать — перечислить в PR с причиной.
- Сначала места с наибольшим числом оценок. Братислава — образец
  (`docs/growth-strategy.md`, раздел 0): полнота не цель, качество — да.

## Файл

`data/cities/<город>/review-insights/<slug>.json`, `slug` — как в
`businesses.csv`. Языки — английский и **каждый язык из `locales`
города** (`city.json`): для Братиславы `en` + `sk`, для Брно `en` + `cs`.

```json
{
  "slug": "veterinarna-ambulancia-kocur",
  "source": "google",
  "google_maps_url": "https://maps.google.com/?cid=...",
  "period_from": "2026-03-26",
  "period_to": "2026-09-26",
  "reviews_in_period": 23,
  "observed_at": "2026-09-26",
  "cards": [
    {
      "topic": "staff",
      "sentiment": "positive",
      "mentions": 14,
      "title": { "en": "…", "sk": "…" },
      "text":  { "en": "…", "sk": "…" }
    }
  ],
  "faq": [
    {
      "q": { "en": "…", "sk": "…" },
      "a": { "en": "…", "sk": "…" },
      "basis": "reviews"
    }
  ]
}
```

- `google_maps_url` — из столбца `google_maps_url` в `businesses.csv`.
- `cards` — **ровно 3**, три самые обсуждаемые темы из: `staff`
  (отношение, объяснения), `results` (результат лечения/стрижки),
  `prices` (как оценивают цены), `waiting` (запись, ожидание), `place`
  (чистота, парковка, доступность), `communication` (телефон, ответы),
  `animals` (как обращаются с животными).
  `sentiment`: `positive` / `mixed` / `negative`. `mentions` — сколько
  **разных** отзывов за период говорят об этой теме, **не меньше 3**.
- `title` — 3–6 слов. `text` — 2–4 предложения, **250–450 символов**
  на каждом языке; по смыслу языки одинаковые.
- `faq` — **3–6** вопросов, которые реально задаёт владелец питомца:
  запись, ожидание, парковка, экзоты, английский, оплата картой,
  неотложка. `basis`: `reviews`, `website` или `both`. Нет надёжного
  ответа — вопрос не включать.

Эталон тона и формата — 10 файлов пилота в
`data/cities/bratislava/review-insights/`.

## Правила

**Честность**
- Писать обобщением: «Most reviewers…», «Several owners mention…»,
  «Viacerí zákazníci…». **Не** от первого лица, без выдуманных историй,
  имён и цитат.
- Негатив не прятать: 4 жалобы из 20 на ожидание — это карточка
  `mixed`. Одни похвалы при заметной критике — нарушение.
- Цены — только как клиенты их оценивают («primerané», «drahšie,
  ale…»). Суммы — только из официального прайса, не из отзывов.
- Отзывы **не копировать**, даже кусками.
- Только последние 6 месяцев от `observed_at`.

**Язык и SEO**
- Сначала текст на языке города, потом английский. Живой язык, как у
  местного редактора, не перевод.
- Тип места и район/город — естественно, **один раз** («veterinár v
  Petržalke»), без повторов ключевых слов.
- Без превосходных степеней от себя («najlepší», «best»); только если
  это мнение большинства, и с атрибуцией («Mnohí ho označujú za…»).

**Сбор**
- Читать отзывы вручную на карточке Google Maps, сортировка «Новые».
  Без скрейперов.
- Никаких персональных данных авторов.

## Проверка и PR

- `cd website && npm run check-city -- <город>` → `READY`. Скрипт
  проверяет формат каждого файла: 3 карточки, 3–6 FAQ, все языки
  города, 250–450 символов, `mentions` ≥ 3, slug = файл = место.
- В описании PR:
  - самопроверка из `docs/playbooks/quality.md` (§2);
  - таблица: место, `reviews_in_period`, темы карточек с `sentiment`,
    число FAQ;
  - места без файла и причина (меньше 20 оценок, меньше 5 отзывов с
    текстом за полгода, нет карточки Google).

Показ на сайте уже сделан (`components/ReviewInsightsSection.tsx`):
блок появляется сам после загрузки данных.

# Инструкция: добавить город (для Antigravity)

Одна сессия Antigravity = **один город**. Сессии на разные города не
пересекаются по файлам, поэтому их можно запускать параллельно с
разных аккаунтов: каждая работает в своей ветке и своих папках.

## Промпт для запуска (владелец копирует и меняет город)

```
Ты — Antigravity, исполнитель проекта pawenn (репозиторий OLLEZHIK/shop).
Прочитай AGENTS.md и docs/playbooks/add-city.md и выполни инструкцию
для города: Košice, страна SK.
Ветка: antigravity/city-kosice. Трогай только data/cities/kosice/ и
website/public/logos/kosice/. Когда закончишь — открой PR в main.
```

Если город большой и его делят между аккаунтами по категориям,
добавьте в конец промпта строку:
`Категории: VET_CLINIC` (или `GROOMING, PET_HOTEL` и т.п.)
и укажите ветку с суффиксом: `antigravity/city-kosice-vet`. Подробнее
в разделе «Деление города между аккаунтами».

---

## 0. Перед началом

- Прочитать `AGENTS.md`. Главное правило для этой работы: **факты не
  выдумывать.** Нет данных — поле пустое, причина в `notes`.
- Проверить, что ветки `antigravity/city-<slug>` ещё нет на GitHub.
  Если есть — город уже в работе у другой сессии: остановиться и
  сообщить об этом.
- **База данных не нужна.** Эта работа — только файлы. Сайт, `prisma`,
  `npm run db:seed` не запускать. Боевая база — Neon, локально
  работать с ней нельзя (`docs/database.md`).
- `<slug>` города — название латиницей без диакритики, в нижнем
  регистре, пробелы → дефис: `Košice` → `kosice`, `Banská Bystrica` →
  `banska-bystrica`.

## 1. Результат: какие файлы создать

```
data/cities/<slug>/city.json          город и его районы
data/cities/<slug>/businesses.csv     все заведения города
data/cities/<slug>/review-insights/   «что говорят клиенты», файл на заведение
website/public/logos/<slug>/          логотипы (если нашлись)
```

Больше ничего не менять. Не трогать `data/*-bratislava.csv`, код сайта
и чужие папки городов.

### 1.1 `city.json`

```json
{
  "name": "Košice",
  "slug": "kosice",
  "country": "SK",
  "locale": "sk",
  "lat": 48.7164,
  "lng": 21.2611,
  "districts": [
    { "name": "Staré Mesto", "slug": "stare-mesto" },
    { "name": "Sídlisko KVP", "slug": "sidlisko-kvp" }
  ],
  "sources": ["https://sk.wikipedia.org/wiki/Košice"],
  "observed_at": "2026-09-25"
}
```

- `country` — код страны ISO из двух букв (`SK`, `CZ`, `AT` …);
  `locale` — код языка города (`sk`, `cs`, `de` …).
- `lat`/`lng` — центр города.
- `districts` — официальные городские части (mestské časti и т.п.).
  Если у города нет официального деления — пустой список `[]`, тогда
  столбец `district` в CSV пустой у всех.
- Slug района строится так же, как slug города. Уникален только в
  пределах города: `stare-mesto` в Košice и в Bratislava — нормально.

### 1.2 `businesses.csv`

**Что собирать для каждого заведения, зачем и на каком языке — в
`docs/card-spec.md` (стандарт карточки).** Ниже — формат файла.

Первая строка — ровно этот заголовок (порядок столбцов важен):

```
category,name,slug,address,district,lat,lng,phone,email,website,instagram,facebook,short_description,short_description_local,description,description_local,opening_hours,hours_source_url,hours_observed_at,emergency_24_7,emergency_note,home_visits,specialties,languages_spoken,photo_urls,google_place_id,google_maps_url,google_rating,google_rating_count,rating_observed_at,logo_file,source_url,observed_at,notes
```

Столбцы `emergency_24_7`, `emergency_note`, `home_visits`,
`specialties` заполняются только у `VET_CLINIC`, у остальных пустые.
Столбцы, которых нет в таблице ниже, описаны в `docs/card-spec.md`.

| Столбец | Что | Правила |
|---|---|---|
| `category` | тип заведения | ровно одно из: `GROOMING`, `VET_CLINIC`, `PET_HOTEL`, `DOG_TRAINING`, `PET_SHOP`, `PET_SITTING` |
| `name` | название | как у самого заведения (вывеска или сайт), без «s.r.o.», если его нет в вывеске |
| `address` | адрес | улица, номер, индекс, город: `Hlavná 12, 040 01 Košice` |
| `district` | slug района из `city.json` | или пусто, если не удалось определить |
| `lat`, `lng` | координаты | 5–6 знаков после точки; из Google Maps или OpenStreetMap по адресу |
| `phone` | телефон | в международном формате: `+421 905 123 456` |
| `email` | почта | только публично указанная самим заведением |
| `website` | сайт | официальный сайт или официальная страница в соцсети; `https://…` |
| `short_description` | короткое описание на английском | до 100 символов, своими словами, см. раздел 3 |
| `short_description_local` | то же на языке города | до 100 символов; естественный язык, не дословный перевод |
| `description` | подробное описание на английском | 2–4 предложения своими словами |
| `description_local` | то же на языке города | своими словами, не дословный перевод |
| `google_place_id` | Place ID | если удаётся определить; нужен для будущего перехода на Places API |
| `google_maps_url` | ссылка на место в Google Maps | |
| `google_rating` | рейтинг | ровно как на карточке, например `4.7`; пусто, если оценок меньше 5 |
| `google_rating_count` | число оценок | целое; пусто, если меньше 5 |
| `rating_observed_at` | дата просмотра рейтинга | `YYYY-MM-DD` |
| `logo_file` | имя файла логотипа | только имя файла в `website/public/logos/<slug>/`, например `vetamin.png`; или пусто |
| `source_url` | главный источник данных | официальный сайт заведения, иначе ссылка на Google Maps |
| `observed_at` | дата сбора | `YYYY-MM-DD` |
| `notes` | служебные пометки | что не нашлось и почему; посетителям не показывается |

Текст с запятыми брать в двойные кавычки. Кодировка UTF-8.

## 2. Как собирать (быстрый порядок)

Ориентир — **до 100 заведений на город**, но только реально
существующих и работающих. Сколько нашлось, столько и есть: добивать
до 100 сомнительными записями нельзя. В маленьком городе 30–50 — это
нормально.

Работать **по категориям, по очереди** (не прыгать между ними):

1. **VET_CLINIC:** поиск в Google Maps «veterinár <город>», плюс список
   членов ветеринарной палаты страны (для SK — Komora veterinárnych
   lekárov SR), если он доступен.
2. **PET_SHOP:** «chovateľské potreby <город>», крупные сети
   (Super zoo, Fressnapf, Pet Center) — каждый филиал отдельной строкой.
3. **GROOMING:** «psí salón <город>», «strihanie psov <город>».
4. **PET_HOTEL:** «hotel pre psov <город>», «psí hotel», «mačací hotel».
5. **DOG_TRAINING:** «výcvik psov <город>», «kynologický klub <город>».
6. **PET_SITTING:** «venčenie psov <город>», «opatrovanie zvierat <город>».

Для другой страны — те же запросы на её языке.

Для каждого места: взять список из поиска → открыть карточку в Google
Maps (адрес, телефон, сайт, часы, рейтинг, число оценок, ссылка) →
открыть официальный сайт (что делают, часы, для ветклиник — неотложка
и специализации, логотип, соцсети) → записать строку со всеми полями
из `docs/card-spec.md`. На одно место — **5–8 минут**.

**Второй проход — «что говорят клиенты».** После того как CSV готов,
для мест с ≥ 5 отзывами с текстом за полгода сделать файлы
`review-insights/<slug>.json` по правилам `tasks/ide-review-insights.md`
(язык города вместо `sk`, если город не в Словакии).

**Не включать:**
- закрытые места: «Permanently closed», сайт не работает и нет
  активности за год;
- дубли: одно место с двумя карточками — одна строка;
- заведения без единого способа связи: нет телефона, почты и сайта.

Сети: каждый филиал — отдельная строка со своим адресом. Название
одинаковое — это нормально.

## 3. Тексты: правила

- **Своими словами.** Ни с Google, ни с сайтов, ни из отзывов ничего
  не копировать дословно (авторское право).
- **Только проверяемые факты:** что делают, для кого, чем отличаются
  (`Nonstop`, `CT and ultrasound`, `cats only`, `cage-free rooms`).
- **Запрещено:** «лучший», «профессиональный», «качественный»,
  «доступные цены», а также цены и обещания, которых нет в источниках.
- **Название и район в `short_description` не повторять**: они уже
  есть на карточке.
- Пример:
  - `short_description`: `Nonstop vet with surgery, X-ray and ultrasound.`
  - `short_description_local`: `Nonstop ambulancia s chirurgiou, röntgenom a sonografom.`

## 4. Рейтинг Google

- Рейтинг и число оценок — ровно как на карточке, без округления.
- **Меньше 5 оценок — оба поля пустые.** На сайте такой рейтинг не
  показывается.
- Сверять адрес: у филиалов сетей свои карточки.
- **Юридически:** условия Google Maps запрещают массовый скрейпинг.
  Смотреть и записывать вручную или полуавтоматически, без скриптов
  с обходом защиты. Перед массовым масштабированием рейтинг переходит
  на официальный Places API — поэтому важен `google_place_id`.

## 5. Логотипы

- **Только** с официального сайта заведения или его официальной
  страницы в соцсети: логотип в шапке, `apple-touch-icon`, `og:image`
  (если это логотип). **Картинки из Google Maps не брать.**
- Файл: `website/public/logos/<slug-города>/<любое-имя>.png|svg|webp`,
  имя латиницей без пробелов. Это же имя вписать в `logo_file`.
- Не меньше 128 px по короткой стороне, не больше 100 КБ (сжать),
  желательно квадрат, прозрачный или белый фон.
- Нет логотипа, он размытый, или это фото помещения — `logo_file`
  пустой. Сайт покажет инициалы. Логотипы не рисовать и не генерировать.

## 6. Деление города между аккаунтами

Если в промпте указано `Категории: …`:
- собирать только эти категории;
- писать в файл `data/cities/<slug>/businesses-<суффикс>.csv`, где
  `<суффикс>` — суффикс ветки (`vet`, `shops` …). Заголовок тот же.
  Сайт читает все файлы `businesses*.csv` в папке города;
- **`city.json` создаёт только сессия, у которой в списке есть
  `VET_CLINIC`.** Остальные его не создают и не меняют: иначе будет
  конфликт при слиянии. Районы для столбца `district` посмотреть в её
  ветке или взять из официального списка района города (slug — по
  правилу выше).

## 7. Проверка перед PR

- CSV открывается как таблица; в каждой строке столько же столбцов,
  сколько в заголовке.
- `category` — только из шести значений; `district` — только slug из
  `city.json` или пусто.
- `short_description` и `short_description_local` не длиннее 100
  символов.
- Каждый текст есть на двух языках (`docs/card-spec.md`, «Проверка
  перед PR»).
- У каждой строки есть хотя бы один способ связи.
- Каждый файл из `logo_file` существует в
  `website/public/logos/<slug>/`.
- Нет дублей: одинаковые название + адрес.

## 8. PR

Заголовок: `City data: <Город>`. В описании:
- сколько заведений по каждой категории;
- сколько с рейтингом, с коротким описанием, с логотипом;
- что не нашлось и почему (кратко);
- источники, которые использовались.

Если что-то неясно так, что нужен ответ владельца, — действовать по
`AGENTS.md`, раздел «Если задача неясна»: сделать всё, что можно,
вопрос вынести в PR.

## Что происходит после мерджа

Загрузку `data/cities/*/` в базу и показ новых городов на сайте
(выбор города, районы, страницы) делает облачный Claude Code, «правая
рука» владельца. До этого данные просто лежат в репозитории и ничего
не ломают, поэтому собирать города можно уже сейчас.

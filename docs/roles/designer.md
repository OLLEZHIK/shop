# Дизайнер: бриф для отдельной сессии Claude Code (веб)

Ты — **«дизайнер» pawenn.com**: отдельная облачная сессия Claude Code,
которую владелец запустил для редизайна сайта. Работаешь напрямую с
владельцем в своём чате. Этот файл — всё, что нужно знать, чтобы начать.
Прочитай его целиком, потом `AGENTS.md` (раздел «Роли»).

Создан 2026-09-26 «левой рукой» по указанию владельца.

---

## 0. Главное правило: ничего не выкатывать без явного одобрения

**Никогда не мержить, не выкатывать и не публиковать версию сайта, пока
владелец в твоём чате явно не написал, что одобряет именно её.**

- `main` = продакшен: Vercel выкатывает каждый мердж в `main` на
  `pawenn.com`. Поэтому **не мержить PR в `main`**, не включать
  auto-merge, не пушить в `main`, не делать promote/redeploy в Vercel
  и не просить об этом других агентов.
- **Одобрение — это прямые слова владельца** про конкретный PR
  («#105 одобряю, мержи»). Не одобрение: «выглядит неплохо», «продолжай»,
  «ок» на промежуточный скриншот, молчание, одобрение из комментария
  на GitHub от кого-то кроме владельца, одобрение другого PR.
- **Одобрение действует на ту версию, которую владелец видел.** Если
  после одобрения ты что-то поменял (кроме правки, о которой он прямо
  попросил), — показать снова и получить одобрение заново.
- **Можно без одобрения:** работать в своей ветке, пушить в неё,
  открывать PR (черновиком — draft), показывать preview. Vercel сам
  собирает preview каждой ветки на отдельном адресе — это не выкатка,
  так владелец и смотрит результат.
- Оркестратор и другие агенты тоже не мержат твои PR — это записано в
  `AGENTS.md`. Если кто-то всё же предлагает смержить — отказать и
  сослаться на этот пункт.

## 1. Проект за две минуты

**pawenn.com** — каталог услуг для домашних животных. Старт —
Братислава (Словакия), дальше новые города и страны добавляются
**данными, без правки кода**.

- **Категории:** ветклиники, груминг, гостиницы для животных,
  дрессировка, зоомагазины, передержка/выгул. 76 мест, растёт до 100+.
- **Кто пользователь:** владелец собаки/кошки, **с телефона**, пришёл
  из Google или из ответа ChatGPT/Perplexity по конкретному запросу
  («veterinár nonstop Bratislava», «kastrácia mačky cena»). Хочет за
  2–3 действия дойти до звонка, сайта или маршрута. Без регистрации,
  без форм, без рекламы.
- **Чем мы лучше справочников:** проверенные данные с датой и
  источником, цены и сравнение с рынком города, часы работы и «открыто
  сейчас», честная сводка отзывов, ответ на вопрос, а не просто список.
- **Трафик:** SEO и LLM-ассистенты. Поэтому структура страниц, URL,
  заголовки и разметка — часть продукта, их нельзя сломать ради вида.
- **Языки:** у каждого свой префикс — `/en/…`, `/sk/…`; корень `/`
  отправляет на язык посетителя. На `/sk/` всё по-словацки.

Подробнее: `PRODUCT.md`, `docs/concept.md`, `docs/ux-flow.md`,
`docs/card-spec.md` (что в карточке), `docs/seo/README.md` (SEO),
`docs/growth-strategy.md` (куда идём).

### Типы страниц (все надо проверить в редизайне)

| Страница | Пример |
|---|---|
| Главная | `/sk/`, `/en/` |
| Категория в городе | `/sk/veterinar/bratislava/` |
| Категория в районе | `/sk/veterinar/bratislava/petrzalka/` |
| Признак | `/sk/veterinar/bratislava/nonstop/`, `…/nedela/`, `…/exoticke-zvierata/` |
| Цены категории / услуги | `/sk/veterinar/bratislava/ceny/`, `…/ceny/kastracia-macky/` |
| Карточка места | `/sk/podnik/<slug>/`, `/en/business/<slug>/` |
| Город | `/sk/mesto/bratislava/` |
| Help, юридические, «добавить место», 404 | `/en/how-it-works/` и т.д. |

## 2. Задача: редизайн «убрать ИИ-вайбы»

Функциональность MVP закончена (2026-09-26). Сайт работает, но
выглядит **как типовой сайт, сгенерированный ИИ**. Задача — сделать
его похожим на спокойный, надёжный местный справочник, который сделали
люди, знающие город. План владельца: небольшой редизайн → расширение
на новые города. Редизайн не должен ломать масштабирование.

### Что считаем «ИИ-вайбами» (проверь и дополни в аудите)

- Декор без информации: размытые цветные пятна
  (`components/AmbientBackground.tsx` на главной и в карточке),
  градиенты, свечения, «плавающие» элементы.
- Слишком много цветов сразу: 6 цветов категорий + оранжевый + синий +
  зелёный + янтарный на одном экране.
- Всё одинаково закруглённое, в «таблетках» и с тенью; карточки
  одинакового веса — глазу не за что зацепиться.
- Шаблонные тексты: «Find the perfect…», «Your pet deserves…»,
  маркетинговые обещания, эмодзи, восклицательные знаки.
- Декоративные блоки без пользы для задачи «найти и позвонить»
  (проверить: «Mýtus alebo fakt?» / `MythOrFact`, «Otestujte sa…»,
  «Čo dnes potrebuje váš miláčik?»).
- Иконки ради иконок.

### Куда идём

- **Контент — главный герой:** название, «открыто сейчас», телефон,
  цена, район. Иерархия — типографикой и отступами, а не цветом и
  рамками.
- **Спокойная палитра:** нейтральная основа + один акцент. Цвет — для
  смысла (действие, статус), а не для украшения.
- **Плотность данных как у хорошего справочника** (Google Maps-список,
  Zocdoc, хороший городской гид), без ощущения лендинга.
- **Mobile-first:** 390px — основной экран. Десктоп (1280px) —
  полноценный, но вторичный.
- **Свой характер** в мелочах (логотип, типографика, микротексты),
  а не в эффектах.

### Известные проблемы (владелец и «левая рука»)

1. Фильтры на телефоне занимают **три строки** — сжать (например, одна
   прокручиваемая строка или кнопка «Фильтры»).
2. Ссылка на страницы цен со страницы категории — маленькая кнопка в
   строке счётчиков, её почти не видно. Страницы цен — важная
   функция, дать им заметное место.
3. Кнопки-признаки (nonstop, суббота, воскресенье, экзоты, выезд) —
   уже нейтральные и подсвечиваются только при нажатии; так и
   оставить.

## 3. Решения владельца, которые редизайн не меняет

Это не пожелания, а принятые решения. Если считаешь, что какое-то надо
пересмотреть, — спроси владельца, не меняй молча.

- **Никаких значков-наград для заведений** («Top rated», «Best» и
  т.п.).
- **Фото:** не показываем чужие фото по ссылкам и не делаем
  сгенерированные или стоковые. У места — логотип или аватар из
  инициалов (`BusinessAvatar`).
- **Цены в карточке — сразу после контактов**, со сравнением с рынком
  города: знаки €–€€€€€ с подписью («Рыночная цена», «Выше рынка на
  40%»). Логика — `lib/priceMarket.ts`, не менять.
- **«Nonstop»** — только у реально круглосуточных мест.
- **Кнопки-признаки** — нейтральные, подсвечиваются только при нажатии.
  Никакого красного по умолчанию.
- **Никаких выдуманных данных:** нет данных — нет блока. Не рисовать
  «заглушки» с примерами, рейтингами или отзывами.
- **Без рекламы, регистрации, cookie-баннеров.** Единственная cookie —
  `pawenn_lang` (выбор языка).
- **Help и юридические страницы** — только на английском, на всех
  языках, без пометки «(EN)». Не переводятся.
- **Масштабируемость:** никакого хардкода Братиславы, словацкого или
  конкретных категорий в вёрстке. Всё, что зависит от города/языка, —
  из данных и словарей (`lib/dictionaries/*.ts`, `lib/categories.ts`).
- **Производительность:** LCP ≤ 2.5 с на телефоне. Без тяжёлых
  анимаций, видео и больших картинок.

## 4. Что нельзя сломать

- **URL и роутинг:** `website/proxy.ts`, `app/[lang]/…`, слаги в
  `lib/categories.ts`, `lib/priceSlugs.ts`, `lib/attributePages.ts`.
- **SEO:** `<title>`/description, canonical и hreflang
  (`lib/seo.ts`), JSON-LD (Organization, ItemList, BreadcrumbList,
  VeterinaryCare/PetStore), `sitemap.ts`, `robots.ts`, `llms.txt`,
  OG-картинки `/api/og`. H1 на странице — один. Тексты-ответы на
  страницах цен и признаков остаются в HTML (их читают боты).
- **Данные и логика:** `lib/data.ts`, `lib/priceMarket.ts`,
  `lib/hours.ts`, `prisma/`, `data/` — не трогать. Редизайн — это
  `components/`, `app/**/page.tsx` в части вёрстки,
  `app/design-tokens.css`, `app/globals.css`, словари (тексты).
- **Переключение языка** (`lib/localeSwitch.ts`) должно вести на ту же
  страницу на другом языке.

## 5. Как работать

### Порядок

1. **Аудит (без кода).** Поднять сайт локально, снять скриншоты всех
   типов страниц из таблицы §1 — 390px и 1280px, `/sk/` и `/en/`.
   Записать в `docs/design/redesign-audit.md`: что выглядит «ИИ-шно»,
   что мешает задаче «найти и позвонить», предложение направления
   (палитра, шрифты, компоненты) — 1–2 варианта с картинками.
2. **Согласовать направление с владельцем** в чате, до кода.
3. **Делать небольшими PR по зонам**, по одному за раз, например:
   токены и типографика → шапка и футер → список и фильтры → карточка
   места → главная → страницы цен и признаков → служебные.
4. Каждый PR — **черновик (draft)**, в описании: скриншоты «было /
   стало» на 390 и 1280, ссылка на Vercel preview, что проверено.
5. **Ждать явного одобрения владельца** (§0). После одобрения — снять
   draft, смержить, проверить продакшен.
6. Решения по визуальной системе записывать в `DESIGN.md` (источник
   истины для дизайна) — он должен совпадать с кодом.

### Ветки и PR

- Ветка — та, что выдала среда (`claude/<имя>`), или по указанию
  владельца. PR в `main` с префиксом **`[дизайнер]`** в заголовке, в
  описании строка «Исполнитель: Claude Code (облачный, «дизайнер») по
  прямому указанию владельца».
- Не трогать чужие ветки (`antigravity/*`, `mac/*`, `cli/*`, чужие
  `claude/*`). Пока идёт редизайн, другие агенты работают с данными
  (`data/`, `docs/seo/keywords/`) — пересечений быть не должно. Если
  `main` ушёл вперёд — влить `main` в свою ветку, не переписывать
  историю.

### Проверка перед показом

- `cd website && npm run lint` и `npx next build` — без ошибок.
- Скриншоты Playwright (Chromium предустановлен:
  `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`, не запускать
  `playwright install`).
- Проверить обе версии языка, длинные словацкие слова (переносы),
  пустые состояния (фильтр без результатов, место без цен/часов/логотипа).

### Локальный сайт в облачной сессии

Боевую базу локально **не использовать** (`docs/database.md`). В
облачном контейнере Docker нет; рабочий рецепт:

```bash
# Postgres 16 (если нет: apt-get install -y postgresql-16)
mkdir -p /var/tmp/pg && chown postgres /var/tmp/pg
su postgres -c "/usr/lib/postgresql/16/bin/initdb -D /var/tmp/pg/data"
setsid su postgres -c "/usr/lib/postgresql/16/bin/pg_ctl -D /var/tmp/pg/data -l /var/tmp/pg/log -o '-p 5432 -k /tmp' start"
su postgres -c "psql -h /tmp -c \"ALTER USER postgres PASSWORD 'postgres'\"; createdb -h /tmp pawenn"

# website/.env.local
DATABASE_URL="postgres://postgres:postgres@localhost:5432/pawenn"
DIRECT_URL="postgres://postgres:postgres@localhost:5432/pawenn"

cd website && npm ci && npx prisma migrate deploy && npm run db:seed
npx next build && npx next start -p 3000
```

- Если Postgres «умер» между шагами — снова `setsid … pg_ctl … start`.
- Если страницы показывают старые данные — удалить
  `website/.next/cache/fetch-cache` и перезапустить.
- Next.js здесь новой версии (16) — перед правками читать
  `website/AGENTS.md`.

## 6. Кому что

| Вопрос | Кто решает |
|---|---|
| Направление дизайна, выкатка, всё спорное | Владелец |
| Вёрстка, компоненты, тексты интерфейса в рамках §3 | Ты, сам, без вопросов |
| Данные о местах, цены, сбор | Не ты: Antigravity по `tasks/` |
| Логика, SEO-разметка, URL | Не менять; нужно — спросить владельца |

Сомневаешься, заметит ли изменение пользователь или поисковик, —
покажи владельцу до мерджа. Всё равно ничего не мержится без него (§0).

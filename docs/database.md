# База данных — решение и как подключиться

## Решение: Neon (через Vercel Storage), регион Frankfurt

**С 2026-09-24 боевая база — Neon, бесплатный тариф.** Раньше был
Prisma Postgres (project `proj_uhvlbpwgi0bvk3ewj9cky9xr`, database
`db_u1lby7vqe8bru1uh74q3ep7f`), но его бесплатный тариф считает каждую
операцию (100 000 в месяц). Лимит закончился, и все страницы, которые
читают базу, стали отдавать 500 (P6003). У Neon лимит по времени работы
базы, а не по числу запросов, и для MVP этого хватает. Старая база
осталась нетронутой как запасная копия: данные в ней и в Neon одинаковые,
потому что обе заполнены из одних и тех же CSV.

Кроме того, чтения из базы кэшируются на сутки (`website/lib/data.ts`,
`unstable_cache`), так что к базе обращается примерно одна страница
в сутки, а не каждый просмотр.

## Откуда приложение берёт подключение

Всё решает `website/prisma/db-url.ts`:
- **На Vercel** Neon подключён через Storage, и его переменные
  окружения появляются в проекте автоматически. Код ищет их по хосту
  `*.neon.tech`, а не по имени переменной, поэтому префикс,
  выбранный при подключении, неважен. Приложение использует пулованное
  подключение (`-pooler` в хосте), миграции и seed — прямое.
- **Локально** (Neon-переменных нет) берутся `DATABASE_URL` /
  `DIRECT_URL` из `website/.env.local`. Обе должны быть обычными
  `postgres://` строками.

## Локальная разработка — только на своей базе

**Не подключайтесь локально к боевой базе.** Любой локальный запуск
тратит её ресурсы, и из-за этого мы уже однажды положили сайт. Поднимите
локальный Postgres (например, `docker run -p 5432:5432 -e
POSTGRES_PASSWORD=postgres postgres:16`) и в `website/.env.local`
пропишите:

```
DATABASE_URL="postgres://postgres:postgres@localhost:5432/pawenn"
DIRECT_URL="postgres://postgres:postgres@localhost:5432/pawenn"
```

Затем в `website/`: `npx prisma migrate deploy && npm run db:seed`.

## Миграции и seed на Vercel

`npm run build` сначала запускает `website/scripts/db-setup.ts`:
- **Новая пустая база:** применяет миграции и заливает CSV из `data/`.
  Так заполнилась Neon.
- **Production-сборка:** применяет новые миграции
  (`prisma migrate deploy`). Если заведений в базе нет, запускает seed.
- **Preview-сборка на существующей базе:** ничего не трогает, чтобы
  ещё не смёрженный PR не мигрировал и не перезаливал боевые данные.
- **Локальная сборка:** ничего не трогает.

Seed (`website/prisma/seed.ts`) делает upsert по slug, его можно
запускать повторно. Данные о заведениях живут в CSV (`data/*.csv`) —
это источник правды, база из них пересобирается.

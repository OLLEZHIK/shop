# Стандарт карточки заведения

Единый список того, что должно быть у **каждого** заведения в каталоге.
По нему пишутся все задачи на сбор данных: агент получает город (или
город + категории) и собирает для каждого заведения ровно эти поля.
Ничего сверх списка, ничего «по отдельной задаче на одно поле».

Решение владельца (2026-09-25). Где хранится: для новых городов —
`data/cities/<город>/businesses.csv` (см. `docs/playbooks/add-city.md`),
для Братиславы — `data/*-bratislava.csv` (исторический формат, те же
поля; `_local` там называется `_sk`).

## Два языка

Сайт на двух языках: **английский** + **язык города** (для Словакии —
словацкий, `locale` из `city.json`). Правило простое:

- **Тексты** есть в двух версиях: поле без суффикса — английский,
  с суффиксом `_local` — язык города. Обе версии пишутся своими
  словами, естественно для каждого языка, не дословным переводом.
- **Факты** (адрес, телефон, часы, рейтинг, ссылки) от языка не
  зависят: одно значение, сайт сам подписывает их на нужном языке.
- **Коды** (`category`, `specialties`, `opening_hours`) — латиницей
  из фиксированных списков; перевод подписей делает сайт.

## Поля

**Обяз.** — у каждой записи должно быть заполнено, если заведение это
вообще публикует. Нет в открытом доступе — поле пустое, причина в
`notes`. Выдумывать нельзя никогда (`AGENTS.md`).

### 1. Кто это

| Поле | Обяз. | Язык | Что | Откуда |
|---|---|---|---|---|
| `category` | да | код | `GROOMING`, `VET_CLINIC`, `PET_HOTEL`, `DOG_TRAINING`, `PET_SHOP`, `PET_SITTING` | — |
| `name` | да | как есть | Название, как на вывеске/сайте | сайт, Google Maps |
| `slug` | да | латиница | Имя страницы: название без диакритики, нижний регистр, пробелы → `-`. При совпадении — добавить район: `super-zoo-petrzalka` | генерируется |
| `logo_file` | да* | — | Файл в `website/public/logos/<город>/`. **Цель — логотип у ≥ 80 % записей** | сайт → иконки сайта → Facebook → Instagram → бренд сети; порядок и правила — `docs/playbooks/add-city.md`, раздел 5 |

\* пусто только если логотипа нет ни на сайте, ни в соцсетях; где смотрели — в `notes`.

### 2. Описание — на двух языках

| Поле | Обяз. | Что |
|---|---|---|
| `short_description` / `short_description_local` | да | Одна фраза до 100 символов для карточки в списке. Без названия и района (они уже на карточке) |
| `description` / `description_local` | да | 2–4 предложения для страницы заведения: что делают, для кого, чем отличаются |

Правила текстов — `docs/playbooks/add-city.md`, раздел 3 (только
проверяемые факты, без «лучший/профессиональный», ничего не копировать
дословно).

### 3. Где

| Поле | Обяз. | Что |
|---|---|---|
| `address` | да | `Улица номер, индекс Город` |
| `district` | да | slug района из `city.json`, или пусто |
| `lat`, `lng` | да | Координаты, 5–6 знаков. Нужны для карты, маршрута и «Рядом со мной» |
| `google_maps_url` | да | Ссылка на карточку места (кнопка «Маршрут») |
| `google_place_id` | да | Place ID, для будущего перехода на Places API |

### 4. Как связаться

| Поле | Обяз. | Что |
|---|---|---|
| `phone` | да | Международный формат: `+421 905 123 456` |
| `email` | да | Только публично указанный самим заведением |
| `website` | да | Официальный сайт, `https://…` |
| `instagram`, `facebook` | нет | Официальные страницы. У многих грумеров и ситтеров это единственный канал |

Хотя бы одно из `phone` / `email` / `website` обязательно, иначе
заведение не включаем.

### 5. Часы работы

| Поле | Обяз. | Что |
|---|---|---|
| `opening_hours` | да | `mo 08:00-12:00,14:00-19:00; tu 08:00-19:00; …; su closed`. Также `24h`, `closed`, `by-appointment` |
| `hours_source_url` | да | Где взяты часы |
| `hours_observed_at` | да | `YYYY-MM-DD` |

Формат и правила — `tasks/mac-collect-hours-and-vet-services.md`
(или `tasks/done/…` после мерджа).

### 6. Рейтинг

| Поле | Обяз. | Что |
|---|---|---|
| `google_rating` | да | Ровно как на карточке, `4.7`. Пусто, если оценок меньше 5 |
| `google_rating_count` | да | Число оценок. Пусто, если меньше 5 |
| `rating_observed_at` | да | `YYYY-MM-DD` |

### 7. Что говорят клиенты — на двух языках

Отдельный файл на заведение: `data/cities/<город>/review-insights/<slug>.json`
(для Братиславы — `data/review-insights/<slug>.json`). Формат, правила и
порог (≥ 5 отзывов с текстом за полгода) — `tasks/ide-review-insights.md`.
Все `title` / `text` / `q` / `a` — парой `{ "en": …, "<locale>": … }`.

Главное правило оттуда: это **наша сводка** отзывов («N из M пишут…»),
а не отзывы от имени клиентов.

### 8. Только для ветклиник

| Поле | Что |
|---|---|
| `emergency_24_7` | `yes`, если явно «nonstop / 24/7» |
| `emergency_note` | Ограниченная неотложка, на языке города: «pohotovosť do 24:00» |
| `home_visits` | `yes`, если явно есть выезд на дом |
| `specialties` | Коды через `;` из списка в задаче про часы работы |

### 9. Желательно (если легко найти)

| Поле | Что | Зачем |
|---|---|---|
| `languages_spoken` | Коды `en; de; hu; uk; ru …` — только если заведение явно пишет, что обслуживает на этом языке | Сайт на английском: «ветеринар, говорящий по-английски» — частый запрос экспатов |
| `photo_urls` | 1–4 фото через `;`, **только** с официального сайта заведения | Галерея на странице |

### 10. Служебное (посетителям не показывается)

| Поле | Что |
|---|---|
| `source_url` | Главный источник данных |
| `observed_at` | Дата сбора `YYYY-MM-DD` |
| `notes` | Что не нашлось и почему; «possibly closed: …» |

## Проверка перед PR (для каждого агента)

- Каждое **обяз.** поле либо заполнено, либо пусто с причиной в `notes`.
- Все тексты есть в двух языках: нет `short_description` без
  `short_description_local` и наоборот; то же для `description` и
  review-insights.
- `slug` уникален в городе; файл review-insights назван тем же slug.
- В описании PR — таблица заполненности: сколько записей имеют каждое
  поле из разделов 1–8.

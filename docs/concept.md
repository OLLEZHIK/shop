# Концепция проекта: каталог услуг для питомцев (Словакия)

Рабочее название: **Psí kompas** (варианты: «Labky», «Chlpáči»; занятость домена и торговой марки не проверялась).
Дата: 2026-09-19. Статус: концепция для старта разработки. Языки: сайт на словацком, документация на русском.

---

## 0. Коротко

- **Что:** сайт, который помогает владельцу собаки за минуту выбрать салон или услугу в своём городе: каталог с ценами, фильтрами и быстрым контактом. Без рекламы и без регистрации.
- **Старт:** Братислава, грумеры (стрижка, купание, тримминг), 50-60 салонов, собранных вручную.
- **Почему сейчас:** товары для животных в Словакии выросли на 127% по обороту в первом полугодии 2026 (данные Heureka в пересказе Ecommerce Bridge). Спрос на питомцев растёт.
- **Конкуренты:** Modrý psík, Salonprepsy.sk, Zoznam.sk, Azet.sk, Reservio, Bookio (как инструмент записи). В Чехии сильнее: Notino, Reservio, Firmy.cz, VěrnýPes.cz. Это в основном списки без цен и фильтров (проверено по поисковым фрагментам, не по полному анализу сайтов).
- **Отличие:** цены и фильтры под породу и размер собаки, быстрые кнопки «позвонить / сайт / маршрут», чистый дизайн без рекламных блоков.
- **Заработок:** сначала нулевой (3-6 месяцев на трафик), потом платное выделение карточек с отчётом по кликам, затем лиды и партнёрские ссылки. Бронирование и внутренний кошелёк вне ближайшего плана.
- **Кто строит:** агенты (Antigravity, Claude Code) по задачам из этого файла; человек принимает решения и проверяет результат.
- **Чего пока не делаем:** аккаунты пользователей, кошелёк, приложение, отзывы клиентов, корма, ветеринаров, Чехию.

## 1. Цели и принципы

1. **Одна вертикаль, один город:** грумеры в Братиславе. Расширяться только после первых цифр трафика и кликов.
2. **Полезность важнее объёма:** каждая страница отвечает на конкретный вопрос («сколько стоит стрижка йорка в Петржалке»).
3. **Данные наши и проверяемые:** у каждой цены есть источник и дата проверки.
4. **Без рекламы и без регистрации** в MVP. Пользователь ничего не создаёт и ничего не платит.
5. **Честность:** порядок в списке объяснён, платное выделение помечено, отзывы не выдумываются.
7. **Маленькие шаги:** результат каждого этапа можно открыть и проверить в браузере.

## 2. Пользователи и сценарии

Главный пользователь: владелец питомца в Братиславе, который ищет салон и не знает, где смотреть цены и кто подходит.

| Сценарий | Что он делает | Что должен получить (критерий приёмки) |
| --- | --- | --- |
| A. «Салон для йорка в Петржалке» | Ищет в Google, попадает на страницу района или услуги | За 2 клика видит салоны района с ценой для своей породы |
| B. «Сколько стоит стрижка лабрадора» | Ищет цену | Страница породы показывает диапазон цен и таблицу салонов |
| C. «Позвонить сейчас» | На мобильном хочет связаться | Кнопка «Zavolať» видна без прокрутки на карточке и в списке |
| D. «Нужен салон для кошки / нервной собаки» | Ищет специальные условия | Фильтр по особенностям работает и меняет список |

Вторичный пользователь: владелец салона. Ему нужны корректные данные о его салоне и статистика кликов. В MVP он просто пишет на e-mail для исправлений.

## 4. Информационная архитектура и URL (SEO)

Принцип: один URL на один поисковый запрос, страница индексируется только если на ней есть реальное содержание.

```
/                                          главная
/psi-salon/bratislava/                     город, все салоны
/psi-salon/bratislava/{district}/          район (например petrzalka)
/strihanie-psov/bratislava/                услуга по городу
/kupanie-psov/bratislava/
/trimovanie-psov/bratislava/
/cena-strihania-psov/bratislava/           ценовой обзор по городу
/plemeno/{breed}/strihanie/bratislava/     порода + услуга + город
/salon/{slug}/                             карточка салона
/blog/{slug}/                              статьи
/pridat-salon/                             форма «добавить или исправить»
/ako-to-funguje/                           методика и порядок сортировки
/ochrana-osobnych-udajov/  /podmienky-pouzivania/
```

**Обновление (после старта разработки): базовый язык сайта —
английский**, URL-схема выше устарела в части языка. Правильная схема
теперь: `/` (без префикса) = английский, `/sk/...` = словацкий,
добавляется позже. Показанные выше пути на словацком (`/psi-salon/`,
`/strihanie-psov/` и т.д.) нужно будет заменить на английские
эквиваленты **после отдельного SEO-исследования английских ключевых
слов** (объёмы поиска на английском для Братиславы, скорее всего,
сильно ниже словацких — это отдельный риск, который стоит явно
учитывать при переходе на английскую базу, а не просто механически
перевести словацкие URL). Не переводить slug'и «на глаз» без
исследования — см. принцип «не додумывать» в `AGENTS.md`.

Правила:
- Страница района, услуги или породы получает `index` только если на ней минимум 3 салона или таблица цен из проверенных данных. Иначе `noindex` и не попадает в sitemap.
- Канонические URL, чистая иерархия хлебных крошек, внутренняя перелинковка «город → район → услуга → порода → салон».
- Для словацкого языка (второй язык) заложить структуру `/sk/` и теги hreflang, реализовать после английской версии.

## 6. Модель данных (эскиз для Prisma / Postgres)

```prisma
model City        { id Int @id @default(autoincrement()) name String slug String @unique }
model District    { id Int @id @default(autoincrement()) cityId Int name String slug String @unique }
model Breed       { id Int @id @default(autoincrement()) name String slug String @unique sizeClass SizeClass coatNotes String? }
enum SizeClass    { MINI SMALL MEDIUM LARGE XL }

model Salon {
  id            Int      @id @default(autoincrement())
  name          String
  slug          String   @unique
  address       String
  districtId    Int
  lat           Float?
  lng           Float?
  phone         String?
  email         String?
  website       String?
  openingHours  Json?
  animals       String[]      // dog, cat
  specialties   String[]      // veľké psy, mačky, šteniatka, hypoalergénna kozmetika ...
  status        SalonStatus @default(DRAFT)   // DRAFT, PUBLISHED, REMOVED
  featured      Boolean  @default(false)
  verifiedAt    DateTime?
  sourceUrls    String[]      // odkiaľ sú údaje
  notes         String?
}
enum SalonStatus { DRAFT PUBLISHED REMOVED }

model Service     { id Int @id @default(autoincrement()) name String slug String @unique }   // strihanie, kupanie, trimovanie ...
model PriceItem {
  id         Int @id @default(autoincrement())
  salonId    Int
  serviceId  Int
  sizeClass  SizeClass?
  breedId    Int?
  priceFrom  Decimal
  priceTo    Decimal?
  currency   String @default("EUR")
  sourceUrl  String
  observedAt DateTime
}
model ClickEvent  { id Int @id @default(autoincrement()) salonId Int type ClickType page String referrerHost String? createdAt DateTime @default(now()) }
enum ClickType    { CALL WEB ROUTE EMAIL }
```

Правила данных:
- Каждая цена и каждый контакт имеют `sourceUrl` и дату `observedAt` / `verifiedAt`.
- Показываем «Údaje overené: {дата}». Данные старше 90 дней помечаются для перепроверки.
- ClickEvent не хранит IP, cookie и данные пользователя.

## 7. Сбор и качество данных

**Источники:** только публичные сайты и прайс-листы самих салонов, плюс данные, которые прислали сами салоны. Не использовать данные Google Places (кроме идентификатора места), не копировать чужие отзывы.

**Порядок:**
1. Составить список 50-60 салонов Братиславы из публичных источников (сайты салонов, каталоги для поиска, карты для ориентира, но не как источник рейтингов).
2. Для каждого салона заполнить CSV (см. приложение C): адрес, район, телефон, e-mail, сайт, услуги, цены по размеру, особенности, ссылки-источники, дата.
3. Проверить телефон и сайт (работает ли ссылка).
4. Загрузить в базу скриптом импорта.
5. Отправить владельцу салона короткое письмо о том, что салон добавлен, с возможностью исправить или удалить данные (шаблон в приложении A). Перед массовой рассылкой уточни правила нежелательной коммерческой рассылки в Словакии, на старте пиши индивидуально.

**Качество:** второй проход (другой агент или человек) выборочно сверяет 20% записей с источниками. Не публиковать салон, у которого нет хотя бы адреса, телефона или сайта и одной цены.

**GDPR (общий подход, юридически проверить):** публиковать только деловые контакты салонов, которые уже публично доступны; давать простой способ исправить или удалить данные; не собирать персональные данные посетителей в MVP.

## 8. Функции MVP

- **Фильтры:** район, услуга, размер собаки, вид животного (собака, кошка дальше добавятся и другие сначала только собака кошка ), диапазон цены, 
- **Сортировка:** по цене, по расстоянию (если пользователь разрешил геолокацию), по умолчанию порядок ротации (равные шансы).
- **Кнопки контакта:** `tel:` для звонка, ссылка на сайт салона (новая вкладка), ссылка на маршрут (карты по выбору пользователя), e-mail.
- **Прозрачность порядка:** страница «Ako to funguje» объясняет, как формируется список. Платные места позже помечаются «Partner» и не смешиваются с обычным порядком без пометки.
- **Форма «добавить / исправить»:** отправка на e-mail владельца проекта, без хранения лишних данных.
- **Без отзывов в MVP.** Отзывы клиентов добавляются позже и только настоящие: подтверждённые, с описанием проверки.

## 9. Аналитика и клик-трекинг

- События: звонок, переход на сайт, маршрут, e-mail; страница-источник; хост реферера.
- Своя точка `/api/click` (серверная запись), без cookie и без хранения IP.
- Для посещаемости выбрать аналитику без cookie (Plausible или Umami). Проверить требования к cookie-баннеру для выбранного решения (закон 452/2021 о электронных коммуникациях, параграф не проверялся) до запуска.
- Ежемесячный отчёт для салона: просмотры карточки, клики по типам. Это основа платной услуги на следующих этапах.

## 11. SEO-план 

**Кластеры запросов** (объёмы не оценены: сверить в Google Keyword Planner и Search Console до финального списка страниц):
- город и услуга: «psí salón Bratislava», «salón pre psov Bratislava», «strihanie psov Bratislava», «kúpanie psov Bratislava», «trimovanie psa Bratislava»;
- район: «psí salón Petržalka», «strihanie psov Ružinov» и т.д.;
- цена: «cena strihania psa», «cenník psí salón Bratislava»;
- порода: «strihanie yorkshire teriéra», «strihanie labradora»;
- особые: «salón pre mačky Bratislava», «salón pre veľké psy».

**Контент (первые 10 статей, словацкий):**
1. Ako často chodiť s psom do salónu (по типу шерсти)
2. Koľko stojí strihanie psa v Bratislave (обзор цен по нашим данным)
3. Ako vybrať psí salón: 8 otázok pred návštevou
4. Trimovanie a strihanie: v čom je rozdiel
5. Prvá návšteva šteniatka v salóne
6. Ako pripraviť nervózneho psa na grooming
7. Čo zahŕňa kúpanie a česanie
8. Grooming pre mačky
9. Sezónna starostlivosť o srsť
10. Grooming doma alebo v salóne

**Техническое SEO:** статическая генерация с обновлением, Core Web Vitals (цель: LCP не хуже 2,5 с на мобильном), структурированные данные, sitemap, canonical, правило `noindex` для страниц без содержания, аккуратные 301, подключение Google Search Console и Bing Webmaster Tools.

**Ссылки и упоминания:** ценовое исследование «Cenový prehľad psích salónov v Bratislave» как материал, на который ссылаются; местные блоги и сообщества собачников (без спама); партнёрство с салонами (ссылка на карточку с их сайта). Гарантировать сроки роста трафика нельзя: у нового сайта это обычно месяцы.

## 14. Как устроен поток с агентами

**Честная поправка:** из этого чата я не могу входить в твои аккаунты Antigravity и управлять ими. Рабочая схема такая:

1. В репозитории лежат `AGENTS.md` (правила), `docs/concept.md` (этот файл) и `tasks/` (задачи с критериями приёмки).
2. Ты запускаешь сессию агента (Antigravity или Claude Code) на **одну задачу** из списка ниже. Агент читает `AGENTS.md` и задачу, делает работу, коммитит в свою ветку.
3. Результат (ссылка на превью, дифф, вывод тестов) ты приносишь мне в чат. Я проверяю по критериям и пишу следующую задачу или правки.
4. Несколько аккаунтов можно использовать параллельно на независимых задачах (например, данные и вёрстка), но не на одном и том же файле.

**Роли:** Orchestrator (я в чате), Builder (агент кода), Data (агент сбора данных), Content (агент статей), QA (агент тестов).

**Definition of Done для любой задачи:** сборка проходит, тесты проходят, страница открывается на мобильном, изменения описаны в коммите.

**Человек решает и проверяет:** название и домен, юридические тексты, отправку писем салонам, публикацию, цены на платные услуги.

**Экономия токенов:** контекст проекта держим в `AGENTS.md`, а не повторяем в каждой задаче; задачи маленькие (1-3 часа работы агента).

### Шаблон `AGENTS.md`

```md
# AGENTS.md
Проект: каталог услуг для питомцев в Словакии (старт: салоны для собак в Братиславе).
Язык сайта: словацкий. Документация: русский. Концепция: docs/concept.md.

## Стек
Next.js (App Router) + TypeScript, Tailwind, Prisma + Postgres, Playwright.

## Команды
npm run dev | npm run build | npm run lint | npm run test | npm run db:migrate | npm run db:seed

## Правила
- Не хранить и не копировать данные Google Maps / Places (кроме place_id). Не копировать чужие отзывы. Не писать фальшивые отзывы.
- У каждой цены и контакта есть sourceUrl и дата проверки.
- Без рекламы, без регистрации, без cookie-трекеров в MVP.
- Тексты интерфейса на словацком. Не выдумывать факты о салонах.
- Страницы без реальных данных: noindex и не в sitemap.
- Если что-то неясно, остановись и задай вопрос, не додумывай.

## Готовность задачи
Сборка и тесты проходят, описание изменений в коммите, критерии приёмки из tasks/*.md выполнены.
```

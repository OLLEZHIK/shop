# Задача: редизайн главной страницы (hero-поиск, новые блоки)

**Исполнитель:** Claude Code CLI (локальный)
**Роль:** Builder agent.
**Тип:** визуальный редизайн, объём большой.
**Ветка:** `cli/redesign-homepage`
**Зависимости:** требует смёрженную `cli-redesign-design-system`
(токены цветов/шрифтов/теней, компонент ambient-фона) — начинать
после её мерджа.

## Контекст

ТЗ владельца от 2026-09-22 (референс Zocdoc). Текущая главная
(`app/page.tsx`, `components/HomeSearch.tsx`) уже имеет рабочий
3-шаговый поиск с мобильным оверлеем и реальными счётчиками из БД —
логику поиска (редирект на `/{category}/{city}/{district}/`) не
ломать, редизайн — про внешний вид и состав блоков, не про то, как
устроен сам переход к результатам.

## Что сделать

1. **Hero-блок:** заголовок «Find pet services in Bratislava» крупным
   выразительным шрифтом (заголовочный из `design-tokens.css`).
   Ambient-фон из задачи `cli-redesign-design-system` — на этой
   странице.
2. **Поисковая панель:** единый монолитный блок с мягкой тенью
   (токен `--shadow-card` или отдельный, если нужен более
   выразительный именно тут). Три поля:
   - Питомец (dog/cat) — кастомный dropdown с SVG-иконками слева от
     текста (не эмодзи). Можно переиспользовать `path`/`svg`-стиль из
     финального логотипа (собачье ухо/кошачье ухо уже нарисованы в
     `design/logo-concepts/13-duo-puppy-ears.svg` — не обязательно
     копировать 1-в-1, но стилистически согласовать).
   - Услуга — кастомный dropdown, 6 категорий.
   - Район — кастомный dropdown, районы Братиславы из БД (`getAllDistricts()`).
   Дропдауны: `border-radius` 12-16px на контейнере списка, hover
   пунктов — приглушённые брендовые тона (не браузерный синий фокус
   по умолчанию — переопределить). Кнопка поиска — в правой части
   блока.
   Мобильный оверлей-флоу (шаги 2-3 полноэкранные) — сохранить
   поведение, обновить только внешний вид под новую стилистику.
3. **Убрать с текущей главной:**
   - Блок цифровых счётчиков («10 Salons, 34 Vet Clinics…»).
   - Текстовый блок «How it works» (ссылка на `/how-it-works/`
     остаётся в футере/хедере — саму страницу не трогать, убирается
     только тизер-блок с главной).
4. **Новый блок «Популярное рядом»:** сетка 3-4 карточки. **Важно:**
   владелец в ТЗ написал «на основе геолокации» — geo-permission от
   браузера сюда не добавляем (лишний UX-барьер и запрос разрешения
   ради MVP с одним городом); вместо этого — реально самое
   популярное **по данным БД** для дефолтного города
   (`getDefaultCity()` + переиспользовать/расширить
   `getDistrictCounts()` из `lib/data.ts`, аналогично можно сделать
   агрегат «топ-1 бизнес по категории» — например, по количеству
   `PUBLISHED`-отзывов или просто первый по `shuffleDeterministically`,
   если отзывов пока ни у кого нет, что сейчас и есть). Явно
   реальные данные, не выдуманные — если по какой-то категории нет
   ни одного бизнеса, эта карточка просто не рендерится.
5. **Блок спец-рекомендаций/партнёров:** в схеме уже есть
   `Business.featured: Boolean` — рендерить блок только если есть хотя
   бы один бизнес с `featured: true` (сейчас, вероятно, таких нет — то
   есть в MVP блок не появится, и это правильно: **не выдумывать
   партнёрский контент** — ни рекомендованный корм, ни фейковые
   сервисы. Просто собрать блок готовым к моменту, когда появятся
   реальные партнёрские данные).
6. **Блок «полезные советы и факты»:** 3-5 мини-карточек. **Не
   выдумывать статистику** («собаки с ежегодным чекапом живут
   дольше» из примера в ТЗ — ровно то, чего делать нельзя без
   источника, см. `AGENTS.md`/`PRODUCT.md`, принцип «не выдумывать
   факты»). Два допустимых варианта, выбрать один:
   (а) общие практические советы по уходу без числовых
   утверждений («Стрижка когтей раз в 3-4 недели предотвращает
   растрескивание» — практический совет, не статистика, не нужен
   источник на конкретную цифру про продолжительность жизни);
   (б) если хочется цифр — только с реальной ссылкой на источник
   (аналогично `PriceItem.sourceUrl`), тогда это не входит в объём
   этой задачи (нет времени/данных сейчас) — сделать заглушку с
   практическими советами (вариант а), реальную статистику с
   источниками — отдельная будущая задача. Не должно выглядеть
   AI-шаблонно: разный формат карточек, не одна и та же структура
   «Заголовок: факт» пять раз подряд.

## Definition of Done

- Hero + единая поисковая панель с кастомными dropdown'ами (иконки,
  скругления, брендовый hover) на месте, поиск по-прежнему реально
  редиректит на страницу категории с фильтрами.
- Счётчики и текстовый блок "How it works" убраны с главной.
- Блок "Популярное рядом" — реальные данные из БД, не выдумка.
- Партнёрский блок скрыт, если нет ни одного `featured` бизнеса (не рендерит фейковый контент).
- Блок советов — без невалидированных статистических утверждений.
- `npm run build` и `npm run lint` проходят.
- Проверено в браузере (Playwright MCP), мобильный и десктопный viewport, весь флоу поиска до результата.
- PR открыт в `main`.

## Если что-то неясно

Формулировки советов/конкретный набор карточек "популярное" — на
усмотрение исполнителя. Если структурно неясно (например, как именно
агрегировать "популярность" при полном отсутствии отзывов у всех
бизнесов) — решить самостоятельно разумным способом и коротко
пояснить в PR, не останавливаться.

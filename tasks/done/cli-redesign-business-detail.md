# Задача: редизайн страницы бизнеса (детальная карточка)

**Исполнитель:** Claude Code CLI (локальный)
**Роль:** Builder agent.
**Тип:** визуальный редизайн, объём большой.
**Ветка:** `cli/redesign-business-detail`
**Зависимости:** требует смёрженную `cli-redesign-design-system`
(токены, ambient-фон компонент). Может идти параллельно с
`cli-redesign-listing-cards` (разные страницы), но не начинать раньше
`cli-redesign-design-system`.

## Контекст

ТЗ владельца от 2026-09-22. Меняется `app/business/[slug]/page.tsx` и
компоненты вокруг неё. JSON-LD, click-трекинг, форма отзыва, verified-
бейдж, условный рендеринг блоков без данных (PR #32) — не трогать
логику, только внешний вид и состав блоков.

## Что сделать

1. **Фон:** ambient-компонент из `cli-redesign-design-system`
   (тот же, что на главной — не делать второй похожий, переиспользовать).
2. **Хедер карточки:** крупное название, тип заведения + адрес,
   блок рейтинга (звёзды + средний балл + кликабельный счётчик
   отзывов — скролл/якорь к блоку отзывов ниже на странице).
3. **Галерея фото:** сетка (1 крупное + 3-4 миниатюры) или слайдер во
   всю ширину контентной зоны. Та же оговорка про отсутствие реальных
   `photoUrls`, что и в `cli-redesign-listing-cards` — сделать
   компонент общим/переиспользуемым между карточкой в списке и этой
   страницей, а не двумя отдельными реализациями. Заглушка — та же.
4. **О компании:** структурированный блок — описание (`notes`, если
   есть, иначе блок не рендерится), часы работы (`openingHours` — уже
   есть в схеме как `Json?`, сейчас пустое почти у всех — рендерить
   только если заполнено), специальности/услуги (`specialties`).
5. **Карта:** встроенная интерактивная карта с пином адреса бизнеса.
   **Решение по реализации (чтобы не тянуть платный API):** Google
   Maps Embed через `iframe` с параметром `q=` (адрес бизнеса,
   URL-кодированный) — `https://www.google.com/maps?q={address}&output=embed`.
   Это не требует API-ключа и ничего не стоит (в отличие от Maps
   JavaScript API/Places API, которые требуют биллинг-аккаунт Google —
   решение о подключении платного API есть смысл выносить владельцу
   отдельно, не в объёме этой задачи; embed-iframe закрывает
   потребность "увидеть локацию и маршрут" без этого). Если
   `business.lat`/`business.lng` есть — можно использовать их вместо
   текстового адреса для точности (`q=lat,lng`), иначе fallback на
   `address`.
6. **Отзывы:** список (уже есть, PR #32) — визуально обновить под
   новые токены, логику/форму не менять.
7. **Блок "Похожие поблизости":** список бизнесов той же категории и
   того же города (переиспользовать `searchBusinesses({ category,
   citySlug })` из `lib/data.ts`, исключить текущий бизнес по `id`,
   ограничить 3-4 карточками) — используя тот же обновлённый
   `BusinessCard` из `cli-redesign-listing-cards` (не отдельная мини-
   версия карточки). Если в категории/городе больше никого нет —
   блок не рендерится.

## Definition of Done

- Хедер карточки, галерея (с общей заглушкой из `cli-redesign-listing-cards`), блок "О компании", карта, отзывы — все на месте, соответствуют новым токенам.
- Карта реально показывает адрес бизнеса (embed без API-ключа).
- Блок "Похожие поблизости" использует реальные данные из БД, не рендерится при их отсутствии.
- `npm run build` и `npm run lint` проходят.
- Проверено в браузере (Playwright MCP) на реальной странице бизнеса, мобильный и десктопный viewport.
- PR открыт в `main`.

## Если что-то неясно

Компоновка блоков (сетка vs слайдер для фото, порядок блоков) — на
усмотрение исполнителя. Если платная карта (JS API) кажется явно
нужной вместо embed — не подключать самостоятельно (это трата денег),
написать об этом в PR как открытый вопрос владельцу.

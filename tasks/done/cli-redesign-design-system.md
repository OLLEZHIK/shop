# Задача: дизайн-система (токены), хедер, ambient-фон — фундамент редизайна

**Исполнитель:** Claude Code CLI (локальный)
**Роль:** Builder agent.
**Тип:** визуальный редизайн, объём средний. Фундамент для трёх следующих
задач редизайна (`cli-redesign-homepage`, `cli-redesign-listing-cards`,
`cli-redesign-business-detail`) — начинать первой, остальные три
используют токены и компоненты отсюда.
**Ветка:** `cli/redesign-design-system`
**Зависимости:** нет.

## Контекст

Владелец прислал подробное ТЗ на редизайн (2026-09-22, зафиксировано
здесь и в трёх соседних задачах). Референс — Zocdoc: лёгкость, акцент
на поиске, карточная структура, минимум визуального шума. Текущий
`website/app/globals.css` уже содержит `:root`/`@theme inline` с
брендовыми цветами — это ядро, из которого вырастает эта задача, не
переписывать с нуля.

**Скил `impeccable`:** в корне `DESIGN.md` уже есть маркер
`<!-- impeccable:design-schema 1 -->` — то есть этот файл осознанно
писался под формат, который читает дизайн-ревью инструмент/скил
Impeccable (см. упоминание и в `PRODUCT.md`). Если у исполнителя
локально есть скил `impeccable` — использовать его при этой задаче
(и при трёх соседних `cli-redesign-*`) для ревью/валидации результата
редизайна и для обновления `DESIGN.md` под новую схему (новые токены,
шрифт, ambient-фон, pill-hover) в формате, который скил ожидает — не
просто вручную переписывать раздел текстом. Если скила нет в текущем
окружении — делать как обычно по этому файлу, ничего не блокируется.

## Что сделать

1. **Единый файл дизайн-токенов** (то, о чём явно попросил владелец —
   «чтобы быстро экспериментировать, не меняя код везде»):
   `website/app/design-tokens.css`, импортируется один раз в
   `globals.css` перед остальными стилями. Содержит:
   - Цвета (перенести существующие `--brand-orange`/`--brand-blue`/
     `--brand-green`/`--brand-amber`/`--background` из `globals.css`
     сюда, ничего не меняя по значению — это перенос, не смена
     палитры).
   - Шрифты: заголовки — **Plus Jakarta Sans** (решение по умолчанию
     из вариантов, которые перечислил владелец в ТЗ — геометричный
     гротеск с характером, бесплатный, есть на Google Fonts, хорошо
     сочетается с уже использующимся Inter) — подключить через
     `next/font/google`, не через `<link>` тег (иначе штраф к LCP).
     Тело/UI — Inter, как было, не трогать. Если владельцу шрифт не
     понравится — заменить потом можно, поменяв 2-3 строки в этом же
     файле, это и есть цель токенов.
   - Радиусы (`--radius-card`, `--radius-pill` и т.п.), тени
     (`--shadow-card`, `--shadow-card-hover`) — под карточки и
     dropdown'ы из следующих трёх задач, единые на весь сайт.
2. **Хедер** (`components/Header.tsx`): убрать нижнюю границу
   (`border-b`), сделать полностью прозрачным/на фоне страницы.
   Ссылки меню — без рамок в дефолте; при `hover` — плавно
   проявляющаяся pill-обводка (`border-radius: 999px` или 8-10px,
   на усмотрение по факту) в приглушённых брендовых тонах (не ярких
   `#FF6B35`/`#004E89` — осветлённые/приглушённые варианты через
   `color-mix()` или отдельные `--brand-orange-muted`/`--brand-blue-muted`
   токены). Логотип (уже финальный SVG) — слева, без изменений самого
   значка.
3. **Ambient-фон** — переиспользуемый компонент/CSS-класс (например,
   `components/AmbientBackground.tsx` или утилита `.ambient-blobs` в
   `design-tokens.css`), а не копипаста разметки на каждой странице —
   он понадобится и на главной, и на странице бизнеса (обе задачи
   ниже на него ссылаются). Молочный фон + 2-3 органических
   «дымчатых» пятна (`filter: blur(...)`, `border-radius` неровный —
   можно `border-radius: 40% 60% 55% 45%` и т.п. на `div`, или
   SVG-blob) в двух брендовых цветах, низкая непрозрачность (~10-20%),
   `position: absolute`/`fixed`, `z-index` ниже контента, `pointer-events: none`.
   Силуэты «лапка»/«мордочка» — не обязательно фигуративно точные,
   органическая размытая форма важнее буквальной похожести (это фон,
   не иллюстрация).
4. **Обновить `DESIGN.md`** (корень репозитория) под новую визуальную
   схему — новые токены/шрифт/hover-паттерн хедера/ambient-фон,
   желательно через скил `impeccable`, если доступен (см. выше). Не
   переписывать весь файл — только то, что реально меняется этой
   задачей; остальные разделы (типографика тела, отступы, grid,
   performance budget) не трогать, если их не меняем по факту.
5. **Не трогать** в этой задаче: главную страницу целиком, карточки
   списка, страницу бизнеса — это следующие три задачи, здесь только
   токены + хедер + фон-компонент.

## Definition of Done

- `website/app/design-tokens.css` существует, импортируется в
  `globals.css`, содержит все цвета/шрифты/радиусы/тени одним местом —
  проверяется тем, что смена, например, `--brand-orange` в этом файле
  меняет цвет везде на сайте.
- Хедер без нижней рамки, ссылки без обводки в покое, с плавной pill-обводкой на hover.
- Есть переиспользуемый ambient-фон компонент/класс, подключаемый одной строкой.
- `npm run build` и `npm run lint` проходят.
- Проверено в браузере (Playwright MCP) на мобильном и десктопном viewport.
- PR открыт в `main`.

## Если что-то неясно

Выбор конкретных оттенков/степени blur/формы пятен — на усмотрение
исполнителя, это визуальные детали, не архитектура (принцип
автономности). Если реально непонятно что-то структурное — вопрос в
PR, не гадать.

# Задача: дозаполнить колонку district во всех собранных датасетах

**Исполнитель:** Claude Code CLI (локальный)
**Роль:** Data agent.
**Тип:** уборка технического долга, объём умеренный.
**Ветка:** `cli/backfill-districts-all-datasets`

## Контекст

Во всех четырёх собранных файлах колонка `district` пуста почти
везде, хотя список районов Братиславы (17 штук, со slug'ами) уже есть
в `docs/concept.md` (раздел «Приложение B»). Агенты, собиравшие данные,
не сопоставляли адрес с районом. Ручное сопоставление по почтовым
индексам ненадёжно — индексы Братиславы не всегда однозначно совпадают
с официальными районами (это подтверждено на практике: один и тот же
индекс попадался у двух разных районов в предыдущих правках).

## Файлы, которые нужно обработать

- `data/vet-clinics-bratislava.csv` (34 строки)
- `data/salons-bratislava.csv` (10 строк)
- `data/pet-hotels-bratislava.csv` (11 строк)
- `data/other-pet-services-bratislava.csv` (21 строка)

## Что сделать

1. Прочитать список районов и их slug'ов в `docs/concept.md`.
2. Для каждой строки каждого файла определить район **по реальному
   адресу** (улица + номер дома), не только по почтовому индексу —
   индекс можно использовать как подсказку, но не как единственный
   источник истины. Если есть Playwright MCP — можно свериться с
   картой (например, mapy.cz или openstreetmap.org) по адресу, чтобы
   не гадать.
3. Заполнить колонку `district` соответствующим slug'ом.
4. Если для конкретного адреса район определить с уверенностью не
   получилось (например, адрес неполный или на границе районов) —
   оставить пустым и явно написать причину в `notes`, не гадать.
5. Не трогать никакие другие колонки и строки — только `district`.

## Критерии готовности (Definition of Done)

- В каждом файле у строк с определяемым адресом заполнен `district`.
- Ни одного придуманного/предположительного района без уверенности —
  где не уверены, там пусто и есть пояснение в notes.
- Изменения закоммичены в ветку `cli/backfill-districts-all-datasets`,
  запушены, открыт Pull Request в `main`.
- В описании PR — таблица или список: сколько строк в каждом файле
  удалось определить, сколько осталось пустыми и почему.

# Задача: редизайн карточки в каталоге (список категория×город/район)

**Исполнитель:** Claude Code CLI (локальный)
**Роль:** Builder agent.
**Тип:** визуальный редизайн, объём средний.
**Ветка:** `cli/redesign-listing-cards`
**Зависимости:** требует смёрженную `cli-redesign-design-system`
(токены/тени). Может идти параллельно с `cli-redesign-business-detail`
(разные компоненты), но не начинать раньше `cli-redesign-design-system`.

## Контекст

ТЗ владельца от 2026-09-22. Меняется `components/BusinessCard.tsx` и,
если понадобится, `components/CategoryListing.tsx` — сама логика
фильтрации/сортировки/`noindex`/FAQ (уже сделана в PR #32) не
трогать, только визуал карточки.

## Что сделать

1. **Вся карточка — кликабельная ссылка** на `/business/{slug}/`
   (сейчас, скорее всего, кликабельны только отдельные элементы —
   проверить и поправить, если не так).
2. **Hover:** карточка плавно приподнимается (`transform: translateY(...)`),
   тень усиливается (токен `--shadow-card-hover` из
   `cli-redesign-design-system`), появляется тонкий брендовый контур.
3. **Фото/галерея:** крупная область фото в левой части карточки
   (или сверху на мобильном), скруглённые края в стиле остальных
   карточек. Интерактивный слайдер/точки для нескольких фото.
   **Важно:** у всех 76 бизнесов сейчас `photoUrls` пустой (реальных
   фото ещё не собрано, чужие фото с Google Maps и т.п. использовать
   запрещено правилами проекта — см. `docs/design-plan.md` раздел
   2.1). Значит галерея должна:
   - корректно работать и выглядеть готовой, когда фото появятся;
   - **сейчас, пока `photoUrls` пусто, показывать опрятную заглушку**
     (например, силуэт лапы/мордочки на фирменном фоне, не разбитую
     иконку и не пустой прямоугольник) — не блокироваться на
     отсутствии реальных фото, но и не выдавать плейсхолдер за
     настоящее фото бизнеса.
4. **Название, категория, район/город** — как сейчас, актуализировать
   типографику под новые токены.
5. **Рейтинг:** звёзды (5-балльная шкала) + число + количество
   отзывов в скобках — уже есть `averageRating()`/`business.reviews`
   в `lib/data.ts`, рендерить только если есть хотя бы 1 `PUBLISHED`
   отзыв (как и раньше — принцип "нет данных → нет блока", не менять).
6. **Краткое описание (1-2 строки):** в схеме `Business` нет
   отдельного поля под короткое описание — использовать `notes`, если
   заполнено, обрезая до 1-2 строк CSS (`line-clamp`); если `notes`
   пусто — не показывать блок описания вообще (не выдумывать текст
   про бизнес).
7. **Цена в знаках `$`:** новый расчёт в `lib/data.ts` (не хардкодить
   в компоненте) — тир 1-5 считать **относительно других бизнесов той
   же категории** по `priceItems` (квинтили по `priceFrom`), а не по
   выдуманным фиксированным порогам в EUR — сейчас это заведомо
   реально только для груминга (10 салонов с ценами из
   `tasks/done/antigravity-collect-grooming-prices.md`), у остальных
   категорий `PriceItem` нет вообще — для них блок цены просто не
   рендерится (тот же принцип, что и с рейтингом/фото).

## Definition of Done

- Вся карточка кликабельна, hover — подъём + тень + контур.
- Фото-зона со скруглением, с рабочей (пусть пока на заглушках) галереей/слайдером.
- Рейтинг, цена, описание — рендерятся только при наличии реальных данных, ничего не выдумано.
- `npm run build` и `npm run lint` проходят.
- Проверено в браузере (Playwright MCP): на реальной странице категории (например `/vet-clinics/bratislava/`) карточки выглядят по новому дизайну, клик по карточке переводит на страницу бизнеса, мобильный viewport не ломается (кнопки/тач-таргеты ≥44px).
- PR открыт в `main`.

## Если что-то неясно

Конкретная разбивка квинтилей на цену, точный вид заглушки для фото —
на усмотрение исполнителя. Структурные вопросы (например, если
`notes` окажется непригодным полем под описание) — вопрос в PR, не
гадать.

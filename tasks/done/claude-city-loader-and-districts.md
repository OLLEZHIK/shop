## Решения владельца (2026-09-25), из которых следует задача

1. **Стандарт карточки** — `docs/card-spec.md`: единый список полей для
   каждого заведения, тексты на двух языках (EN + язык города).
2. **Данные — по городам:** `data/cities/<город>/` (`city.json`,
   `businesses*.csv`, `prices.csv`, `review-insights/<slug>.json`,
   логотипы в `website/public/logos/<город>/`). Братислава переезжает туда
   же, старые `data/*-bratislava.csv` после переключения удаляются.
3. **Районы агенты больше не собирают.** Сайт определяет район сам по
   координатам. Ссылки на район показываются, только если там ≥ 3
   заведений этой категории.
4. **Цены — только 6 услуг на категорию** (`docs/card-spec.md`, «Цены»),
   с весовыми диапазонами вместо `size_class`. Для зоомагазинов цен нет.
5. **Животных (`animals`) больше не собираем.** Столбец остаётся, старые
   значения работают, новых не будет.

## Что сделать

### 1. Загрузка из `data/cities/*`

- `prisma/seed.ts` читает все папки `data/cities/*/`: `city.json` →
  `City`; все `businesses*.csv` в папке (город может быть поделён между
  агентами по категориям) → `Business`; `prices.csv` → `PriceItem`;
  `review-insights/<slug>.json` → `reviewInsights`.
- **`slug` берётся из столбца `slug`, не генерируется заново.** Для
  Братиславы оркестратор перенесёт текущие slug'и из базы один в один,
  адреса страниц `/business/<slug>/` не меняются. Проверка: slug уникален
  по всем городам, иначе seed падает с понятной ошибкой.
- Логотипы: `logo_file` — имя файла внутри
  `website/public/logos/<город>/`. Существующие логотипы Братиславы
  (сейчас лежат прямо в `website/public/logos/`) перенести в
  `website/public/logos/bratislava/` тем же PR, что переключает загрузку,
  чтобы картинки на проде не пропали ни на один деплой.
- После переключения удалить старые источники: `data/*-bratislava.csv`,
  `data/salon-prices-bratislava.csv`, `data/vet-prices-bratislava.csv`,
  `data/logos-bratislava.csv`, `data/review-insights/` (перенести в
  `data/cities/bratislava/review-insights/`).
- Прогнать seed против своей локальной базы, потом против Neon — по
  `docs/database.md`.

### 2. Районы по координатам

- Границы районов — из OpenStreetMap (административные границы города),
  один раз на город, скриптом в репозитории (например
  `website/scripts/fetch-districts.ts`). Результат коммитится как
  `data/cities/<город>/districts.geojson`, чтобы seed не ходил в сеть.
- Seed: район заведения = полигон, в который попадает `lat`/`lng`. Нет
  координат или нет полигонов у города — район пустой.
- **Slug'и районов Братиславы сохранить как сейчас** (`stare-mesto`,
  `ruzinov`, `petrzalka`…): это адреса уже проиндексированных страниц.
- **Ссылки на район** (фильтр, `DistrictExplorer`, хлебные крошки на
  странице заведения, перелинковка) — **только если в районе ≥ 3
  заведений этой категории**. Страницы районов с < 3 оставить как есть
  (`noindex`, не в sitemap, уже сделано), просто на них не вести.
- Город без районов — нет ни фильтра, ни страниц районов, всё работает.
- Сравнить со старыми данными: сколько заведений Братиславы получили
  другой район, чем был в CSV. Список расхождений — в PR.

### 3. Новые поля карточки (схема + страница заведения)

По `docs/card-spec.md`. В схему (миграция по `docs/database.md`):
`descriptionLocal`, `instagram`, `facebook`, `openingHours` (уже есть,
формат строки — в `tasks/mac-collect-hours-and-vet-services.md` или
`tasks/done/…`), `hoursSourceUrl`, `hoursObservedAt`, `emergency247`,
`emergencyNote`, `homeVisits`, `specialties` (уже есть), `languagesSpoken`.

На странице заведения показать:
- длинное описание на языке страницы (`description` / `descriptionLocal`);
- часы работы по дням, с отметкой «Открыто сейчас» / «Закрыто» (время
  Братиславы, `Europe/Bratislava`);
- для ветклиник: «Nonstop 24/7», ограниченная неотложка, выезд на дом,
  специализации (подписи кодов на двух языках — в словарях);
- Instagram / Facebook рядом с сайтом;
- «Говорим на: …», если есть `languagesSpoken`.

Везде «нет данных → нет блока».

### 4. Цены: 6 услуг

- `Service` засеять кодами и подписями EN/SK из `docs/card-spec.md`,
  раздел «Цены» (5 категорий × 6 услуг).
- `PriceItem`: вместо `sizeClass` — `weightFromKg` / `weightToKg`
  (миграция; `sizeClass` удалить, если больше нигде не нужен).
- На странице заведения — таблица «Цены»: услуга, вес (если есть),
  «от X €», дата проверки и ссылка на источник (`sourceUrl`,
  `observedAt`) — это правило проекта про доверие.
- На карточке в списке — ничего не добавлять в этом PR.

### 5. Фильтры «Открыто сейчас» и «24/7» (ветклиники)

- Фильтр «Открыто сейчас» по `openingHours` для всех категорий.
- Для ветклиник — «Nonstop 24/7» и отдельная индексируемая страница
  `/<lang>/<vet-категория>/<город>/nonstop` (SEO: «veterinár nonstop
  Bratislava», «pohotovosť veterinár»), если таких клиник ≥ 1.

## Не делать

- Не менять slug'и заведений и районов Братиславы.
- Не удалять фильтр по животным: данных новых не будет, но старые есть.
  Если после переключения у какого-то вида животных 0 заведений в
  категории — не показывать этот вид в фильтре этой категории.
- Не трогать `docs/card-spec.md` и плейбук без согласования с
  оркестратором: это контракт для агентов. Если формату чего-то не
  хватает — написать в PR, оркестратор поправит стандарт.

## Готово, когда

- Сайт собирается целиком из `data/cities/*`, старых
  `data/*-bratislava.csv` нет.
- Все старые адреса `/business/<slug>/` и страницы районов с ≥ 3
  заведениями открываются, как раньше (проверить список из sitemap до и
  после).
- Нет ни одной ссылки на страницу района с < 3 заведениями.
- Страница заведения показывает новые поля и цены; проверено в
  Playwright на телефоне и десктопе, скриншоты в PR.
- Seed прогнан против Neon, в PR — вывод seed (сколько заведений, цен,
  review insights загружено по городам).

# Задача: «Что говорят клиенты» — сводка отзывов и FAQ для каждого заведения

**Исполнитель:** Antigravity IDE
**Роль:** Content / research agent.
**Тип:** контент по отзывам, объём большой. Делается в 2 PR: пилот на 10 заведений, после ревью — остальные.
**Ветка:** `antigravity/review-insights`. Для второго PR — `antigravity/review-insights-rest`.
**Зависимости:** нет. Задача **не трогает** `data/*.csv`, пишет только новые файлы в `data/cities/bratislava/review-insights/`, поэтому идёт параллельно с очередью CSV-задач.

## Зачем

Решение владельца (2026-09-24): на странице каждого заведения показать,
что клиенты думают о нём за последние полгода: всё ли понравилось,
какие цены, как с записью и ожиданием. Плюс ответы на самые частые
вопросы. Цель — SEO и ответы для LLM-ассистентов: **уникальный текст
на местном языке**, которого нет больше нигде.

**Главное правило: это не отзывы, а наша сводка отзывов.** Карточки
не пишутся от лица клиента, у них нет автора и своих звёзд. Если
выдавать сгенерированный текст за отзывы клиентов, это фейковые
отзывы: их прямо запрещает закон ЕС о защите потребителей (директива
Omnibus), а Google за такое наказывает весь сайт. Честная сводка
«N из M отзывов пишут, что…» законна и для SEO ценнее.

## Что сделать

Для каждого заведения — один файл `data/cities/bratislava/review-insights/<slug>.json`
(до 2026-09-25 папка была `data/review-insights/`, файлы пилота перенесены туда же).
`slug` — как на сайте (`/business/<slug>/`).

**Пилот (PR 1):** 10 заведений с наибольшим `google_rating_count`, из
них минимум 6 ветклиник. **Остальные (PR 2):** все, у кого за последние
6 месяцев на Google ≥ 5 отзывов с текстом, после мерджа пилота. У кого
меньше — файл не создавать, перечислить в PR.

### Формат файла

```json
{
  "slug": "veterinarna-ambulancia-kocur",
  "source": "google",
  "google_maps_url": "https://www.google.com/maps/place/?q=place_id:ChIJ...",
  "period_from": "2026-03-26",
  "period_to": "2026-09-26",
  "reviews_in_period": 23,
  "observed_at": "2026-09-26",
  "cards": [
    {
      "topic": "staff",
      "sentiment": "positive",
      "mentions": 14,
      "title": { "en": "…", "sk": "…" },
      "text":  { "en": "…", "sk": "…" }
    }
  ],
  "faq": [
    {
      "q": { "en": "…", "sk": "…" },
      "a": { "en": "…", "sk": "…" },
      "basis": "reviews"
    }
  ]
}
```

- `google_maps_url` — из столбца `google_maps_url` в `data/*.csv`.
- `cards` — **ровно 3**. Темы (`topic`) — 3 самые обсуждаемые из:
  `staff` (отношение, объяснения), `results` (результат лечения/стрижки),
  `prices` (как клиенты оценивают цены), `waiting` (запись, ожидание),
  `place` (чистота, парковка, доступность), `communication` (телефон,
  ответы), `animals` (как обращаются с животными, страх, стресс).
  `sentiment`: `positive` / `mixed` / `negative`. `mentions` — сколько
  разных отзывов за период говорят об этой теме.
- `title` — 3–6 слов. `text` — 2–4 предложения, 250–450 символов,
  EN и SK по смыслу одинаковые.
- `faq` — 3–6 вопросов, которые реально задаёт владелец питомца об
  этом месте: нужна ли запись, сколько ждать, есть ли парковка, лечат
  ли экзотов, говорят ли по-английски, можно ли платить картой,
  неотложка. `basis`: `reviews` (ответ по отзывам), `website`
  (официальный сайт), `both`. Нет надёжного ответа — вопрос не включать.

## Правила

**Честность**
- Писать как обобщение: «Most reviewers…», «Several owners mention…»,
  «Viacerí zákazníci…», «Podľa väčšiny recenzií…». **Не** от первого
  лица клиента, без выдуманных историй, имён и цитат.
- Тема попадает в карточку, только если о ней пишут **минимум 3
  разных автора** за период.
- Негатив не прятать. Если 4 из 20 жалуются на ожидание — это должно
  быть в карточке (`mixed`). Карточки из одних похвал при заметной
  критике — нарушение задачи.
- Цены: только как клиенты их оценивают («primerané na Bratislavu»,
  «drahšie, ale…»). Конкретные суммы — только из официального прайса,
  не из отзывов.
- Отзывы **не копировать** дословно, в том числе кусками.
- Период: последние 6 месяцев от `observed_at`. Старые отзывы не
  использовать.

**SEO без спама**
- В тексте естественно, по одному разу, упомянуть тип заведения и
  район/город («veterinár v Petržalke», «dog groomer in Ružinov»), а
  не повторять ключевые слова в каждом предложении.
- Словацкий — живой, как написал бы местный редактор, а не перевод
  английского. Сначала пишется SK, потом EN.
- Без превосходных степеней от себя («najlepší», «best») — только если
  это прямо мнение большинства отзывов, и тогда с атрибуцией
  («Mnohí ho označujú za…»).

**Сбор**
- Читать отзывы вручную на карточке Google Maps (ссылка из CSV),
  сортировка «Najnovšie». Без скрейперов и автоматического сбора.
- Никаких персональных данных авторов в файлах.

## Готово, когда

- PR 1: 10 файлов `data/review-insights/*.json` (теперь в `data/cities/bratislava/review-insights/`) по формату выше.
  Каждый файл — валидный JSON, `cards` ровно 3, `faq` 3–6, все тексты
  EN+SK, `text` 250–450 символов.
- В описании PR — таблица: заведение, `reviews_in_period`, темы карточек
  с `sentiment`, число FAQ.
- PR 2 — после мерджа PR 1 и с учётом замечаний ревью.

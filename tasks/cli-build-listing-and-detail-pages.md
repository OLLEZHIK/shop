# Задача: страницы списка по категориям/районам + карточка бизнеса

**Исполнитель:** Claude Code CLI (локальный)
**Роль:** Builder agent.
**Тип:** новые страницы, объём большой — можно разбить на под-коммиты внутри одной ветки, если удобнее.
**Ветка:** `cli/build-listing-and-detail-pages`
**Зависимости:** требует смёрженную `cli/generalize-business-model-and-seed` (модель `Business` и заполненная БД). Если она ещё не смёржена — проверить перед стартом (см. `AGENTS.md`, шаг 3 самоопределения задачи) и не начинать эту, пока та не готова.

## Контекст

Полное описание блоков каждой страницы — `docs/design-plan.md`,
разделы 3, 4.2-4.4, 5. Не пересказываю здесь всё заново, следуй тому
документу как источнику истины по содержимому страниц. URL-схема (тоже
раздел 3 того файла) рабочая, но зафиксированная — используй её как
есть, не придумывай свою.

## Что сделать

1. **Данные:** заменить чтение CSV в `website/lib/data.ts` на запросы через Prisma Client к модели `Business` (после того как `cli-generalize-business-model-and-seed` её создала). Функции `getAllBusinesses`/`searchBusinesses`/`getBusinessCount`/`getBusinessById` можно оставить сигнатурно похожими, но реализация — через `prisma.business.findMany(...)` с нужными `where`/`include`. `getBusinessById` — заменить на `getBusinessBySlug(slug)` (текущая реализация через `category-index` нестабильна, ломается при любом изменении порядка).
2. **Страница категория × город** — `website/app/[category]/[city]/page.tsx`
   с динамическим сегментом `[city]` (не литеральная папка `bratislava` —
   см. `docs/design-plan.md` раздел 2.2, это нужно, чтобы следующий город
   добавлялся как запись в БД, без нового кода/деплоя), `generateStaticParams`
   читает список городов из модели `City`. Итоговые URL — как в
   `docs/design-plan.md` разделе 3 (для MVP это фактически только
   `bratislava`, но слаг должен приходить из БД, не быть строкой в коде):
   - Блоки по разделу 4.2 design-plan.md.
   - Фильтры: район, вид животного; фильтр по цене — только если у категории есть хоть одна запись `PriceItem` (сейчас, вероятнее всего, нет ни у одной — тогда просто не показывать фильтр, это ожидаемо).
   - Сортировка: по умолчанию — детерминированная псевдослучайная ротация (например, seed от даты, не от `Math.random()` на каждый рендер — иначе SSG/ISR будет давать разный порядок при каждой генерации).
   - `noindex` (через `generateMetadata`) и не в sitemap, если опубликованных бизнесов < 3 в данной выборке.
3. **Страница категория × город × район** — аналогично, вложенный сегмент, тот же компонент списка с доп. фильтром.
4. **Страница карточки бизнеса** — `website/app/business/[slug]/page.tsx`, блоки по разделу 4.4 design-plan.md. Обязательно: JSON-LD (`LocalBusiness`, `BreadcrumbList`, `AggregateRating` только при наличии опубликованных отзывов), три кнопки быстрого действия (`tel:`, сайт, ссылка на карту), блок цены рендерится только при наличии `PriceItem`, verified-бейдж только при наличии `verifiedAt`. В `LocalBusiness` JSON-LD добавить `dateModified` от `verifiedAt` (если есть) — сигнал свежести для поисковых/LLM-ботов, см. `docs/design-plan.md` раздел 8 (GEO/AEO).
4a. **FAQ-блок на странице категория×город (GEO/AEO, `docs/design-plan.md` раздел 8):** короткий блок из 3-5 вопросов-ответов под списком, с `FAQPage` JSON-LD. Вопросы — шаблон на уровне категории (не пишутся руками на город/район), например «Сколько стоит {категория} в {город}?» (ответ — диапазон цен из `PriceItem`, если есть, иначе не показывать этот вопрос), «Сколько {категория} сейчас в {город}?» (ответ — реальный count из БД), «Какие из них проверены?» (доля с `verifiedAt`). Если для вопроса нет данных для ответа — вопрос не рендерится, не выдумывать текст.
5. **Отзывы (раздел 2.1, 4.4 design-plan.md):**
   - Список `PUBLISHED` отзывов на странице бизнеса (имя, оценка звёздами, текст, дата), сортировка — новые сверху.
   - Форма «Оставить отзыв» (имя, оценка 1-5, текст) под списком. Отправка — через новый route handler `POST /api/reviews` (или `/api/business/[slug]/reviews`), создаёт `Review` со `status: PENDING`, простая server-side валидация (непустое имя/текст, `rating` в диапазоне 1-5, ограничение длины текста). После успешной отправки — сообщение «Спасибо, отзыв появится после проверки», **не** добавлять его в список сразу (он ещё не `PUBLISHED`).
   - Ничего сверх этого (без email-подтверждения, без антиспам-капчи, без админки модерации) — это осознанное упрощение объёма этой задачи, модерация делается вручную через прямой доступ к БД, полноценная админка — будущая отдельная задача.
   - Рейтинг на карточке в списке (`BusinessCard`) и на странице бизнеса — среднее по `PUBLISHED`-отзывам; при их отсутствии — не показывать рейтинг вообще.
6. **Фото:** галерея на странице бизнеса рендерит `photoUrls`, если массив не пуст — в MVP он почти наверняка у всех пуст (реальных фото ещё не собрано, см. `docs/design-plan.md` раздел 2.1), поэтому просто не должно быть пустого/сломанного блока, когда данных нет.
7. **Компоненты** (раздел 5 design-plan.md): `BusinessCard` (с фото/аватаром и рейтингом), `FilterPanel`, `QuickActions`, `VerifiedBadge`, `PartnerBadge`, `Breadcrumbs`, `EmptyState`. Выносить в `website/components/` (или уже принятую в проекте структуру, если она появилась в предыдущей задаче).
8. **Клик-трекинг:** при клике по кнопкам быстрого действия — вызов уже спроектированной точки `/api/click` (`ClickEvent`, см. `docs/concept.md` раздел 9) — если этот API ещё не реализован, создать минимальный route handler здесь (POST, без cookie/IP, просто `salonId`/`businessId` + `type` + `page` + `referrerHost`). Если это уже сделано в предыдущей задаче — просто переиспользовать.

## Критерии готовности (Definition of Done)

- Все URL из раздела 3 `docs/design-plan.md` (кроме `/blog/`, он P1) открываются локально и показывают реальные данные из БД.
- `noindex`-правило проверяемо работает (страница с < 3 бизнесами отдаёт `noindex` в метатегах).
- Карточка бизнеса не показывает пустые блоки (цена/часы работы/verified/рейтинг/фото/отзывы) там, где данных нет — не «N/A», а отсутствие блока.
- `LocalBusiness` JSON-LD содержит `dateModified`, когда есть `verifiedAt`. Страница категория×город содержит FAQ-блок с `FAQPage` JSON-LD, вопросы без данных для ответа не рендерятся.
- Форма отправки отзыва реально создаёт `Review` со `status: PENDING` в БД и не показывает его сразу как опубликованный.
- `npm run build` проходит, `npm run lint` проходит.
- Открыт на мобильном viewport (руками или Playwright MCP, если настроен локально) — карточки и кнопки не разъезжаются, кнопки быстрого действия ≥ 44×44px.
- PR открыт в `main` с описанием и, если есть, скриншотами/GIF.
